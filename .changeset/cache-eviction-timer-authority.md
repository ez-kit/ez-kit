fix(store-core): вытеснение записи кэша больше не может «потеряться» навсегда

Срок жизни неотслеживаемой записи считался по двум разным часам: таймер вытеснения ставился
через `setTimeout` (монотонные часы рантайма), а метка `idleSince` — через `Date.now()`
(стенные часы). Часы дрейфуют, поэтому таймер мог сработать, когда стенные часы показывали чуть
меньше `gcTime`. Проверка `isExpired` в этот момент возвращала `false`, запись не вытеснялась —
и, так как проход `removeExpired` ничего не перепланировал, нового таймера не оставалось.
Запись жила до следующего `addObserver`/`removeObserver`/`clear`, то есть фактически вечно,
а подписчики `useFromCache` продолжали видеть якобы вытесненное значение.

Теперь единственный источник истины о сроке — сам таймер: он ставится, только когда уходит
последний наблюдатель, и снимается, как только наблюдатель возвращается. Колбэк стал
поэнтрийным (`evictIfIdle`), так что сработавший дедлайн больше не сканирует всю мапу и не
трогает соседей, чей `gcTime` ещё не вышел. Сверка со стенными часами убрана и из `getInstance`:
раньше её ответ мог измениться без изменения membership, хотя `useFromCache` пересчитывает живой
инстанс только по сигнатуре membership.

Публичный API не менялся.
