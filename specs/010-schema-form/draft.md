# `SchemaForm` поверх композиции формы

**Дата:** 2026-10-12
**Статус:** черновик, обсудить. Вынесено из `specs/009-form-composition/design.md`: `SchemaForm`
ложится поверх headless-слоя, шагов и реестра из 009, поэтому решается после неё.
**Пакеты:** `@ez-kit/form-core`, `@ez-kit/form-react`, `@ez-kit/form-shadcn`, `@ez-kit/form-heroui`

## Что уже решено в 009

- Разделение фабрик: `createForm` без схемного рендерера, `createSchemaForm` — с ним (009, D2).
- Переименование `FormRenderer` → `SchemaForm` (009, D3).
- Схемный визард работает на сторе `form.Steps`: `current`, `goTo(name)`, `steps[i].invalid`,
  `stepErrors`; без автоперехода на шаг с ошибкой; `path` у узла `step` удалён (009, D18 и §5).

Номера D19–D23 ниже сохранены из 009, чтобы старые ссылки в обсуждении читались.

## Решения-кандидаты

### D19. Опции `createSchemaForm`

```ts
createSchemaForm({
	FormElement?,  // вид <form>
	Grid?,         // сетка контейнера; Grid.Item — ячейка с colSpan
	Wizard?,       // поток шагов
	fields?,       // те же, что у createForm; `array` — это ArrayField
	components?,   // тот же открытый набор; он же реестр блоков документа
})
```

Фиксированных имён три — там, где поведение или раскладку держит рендерер: `FormElement`, `Grid`
(вместе с `Grid.Item`, оформлено как `ArrayField` с `Item` в D4) и `Wizard` (вёрстка поверх
`form.Steps`, D18). Все необязательны;
документ, который использует колонки или шаги без переданного компонента, даёт dev-ошибку с именем
слота. `Wizard`, а не `Stepper`: слот получает весь поток, а stepper — лишь индикатор, который кит
рисует внутри.

### D20. Один реестр для JSX и документа

- `component` у блока ищется в `components` той же сборки. `form.Section` в JSX и
  `{ "component": "Section" }` в документе — один компонент, одна регистрация (как поля в спеке 008).
- **Пропс `blocks` у `SchemaForm` удаляется.** `parseFormSchema` проверяет имена по ключам
  `components`, граница доверия остаётся на месте.
- `label` и `description` (общие свойства любого узла) рендерер переводит и передаёт компоненту
  пропсами; `props` передаются сырым JSON.

### D21. Обобщённые контейнеры

- `block` принимает `children`: любой зарегистрированный компонент становится контейнером (`Section`,
  `Card`, `Tabs`).
- **Тип узла `section` удаляется** — секция становится обычным блоком `Section` из кита.
- **Узел `submit` удаляется** — это блок `SubmitButton`: с контекстом ему ничего не нужно от
  рендерера.
- Резерв имени `row` из спеки 003 снимается: строка — это контейнер с `columns`.

### D22. Колонки — свойство любого контейнера

- `columns` (1–4) может стоять на любом узле с детьми; рендерер сам вставляет сетку **внутрь**
  контейнера: `<Card><Grid columns={2}><Grid.Item colSpan>…`. Контейнер получает уже разложенных
  детей и о колонках не знает; контейнер, который раскладывает детей сам, просто не задаёт
  `columns`.
- `colSpan` у узла вне контейнера с `columns` — ошибка парсера (иначе молча ничего не делает).
- Адаптивность — забота кита: `Grid` решает, как сложить колонки на узком экране; документ
  выражает только намерение.
- Сравнение: JSON Forms (`HorizontalLayout` и др.), Formily (`FormGrid` + `GridColumn.gridSpan`) и
  Form.io (компонент `columns`) делают сетку отдельным узлом; SurveyJS — свойством контейнера
  (`gridLayoutColumns`, `colSpan`). Выбран вариант SurveyJS: формат ориентирован на документы от
  конструктора, LLM и бэкенда, где каждый лишний уровень вложенности — место для ошибки, а
  сегодняшний `section.columns` не ломается. Отдельный «узел-сетка» при этом выражается контейнером
  без своей вёрстки.

### D23. Визард и ошибки на других шагах

- Автоматического перехода на шаг с ошибкой **нет**: пользователь сам решает, куда идти.
- В пропсах `Wizard` появляется `steps[i].invalid` — на шаге есть ошибки валидации или
  `serverErrors`; кит подсвечивает шаг в своём степпере.
- В пропсах `Wizard` появляется `goTo(name)`: назад — свободно, вперёд — только на уже пройденные
  шаги, чтобы не перепрыгнуть непроверенный.
- Правило показа ошибок поля расширяется: после попытки сабмита ошибки видны независимо от
  `isTouched`. Иначе поля несмонтированного шага не получают пометку «тронуто», и вернувшийся
  пользователь ошибок не увидит.
- В JSX то же поведение даёт `form.Steps` (D18); схемный визард работает поверх него.

## Ломающие изменения

| Было                                             | Стало                                             |
| ------------------------------------------------ | ------------------------------------------------- |
| узел `section`                                   | блок `Section` из `components`                    |
| узел `submit`                                    | блок `SubmitButton` из `components`               |
| пропс `blocks` у `FormRenderer`                  | `components` сборки                               |
| `Section` / `GridItem` / `Wizard` в `components` | `Grid` (+ `Grid.Item`) и `Wizard` — опции фабрики |
| резерв `row`                                     | снят                                              |

## Тестирование

- блок с детьми и `columns` на произвольном контейнере; `colSpan` вне колонок — ошибка
  парсера; имена `component` проверяются по `components`; `steps[i].invalid` и `goTo` с запретом
  перехода вперёд на непройденный шаг; ошибки видны на вернувшемся шаге после попытки сабмита.
