# Spec Delta

## Purpose

Модалка создания и редактирования строки в data-grid: дефолтная форма из колонок, её поля для
своей раскладки и контракт, по которому разработчик подставляет любую свою форму, а грид отвечает
за открытие, начальные значения и сохранение.

## ADDED Requirements

### Requirement: Модалка рендерит слот FormModal

Когда `creating.mode` или `editing.mode` равен `'modal'`, грид SHALL рендерить зарегистрированный
слот `FormModal`, а в его `children` — сгенерированную форму из колонок. Пока форма закрыта,
модалка SHALL ничего не рендерить.

#### Scenario: Форма создания открывается в слоте кита

- **WHEN** грид с `creating: { mode: 'modal' }` получает `creating.start()`
- **THEN** рендерится зарегистрированный `FormModal` с заголовком создания и полями всех колонок, которые входят в форму создания

#### Scenario: Закрытая форма ничего не рендерит

- **WHEN** форма создания закрыта
- **THEN** `FormModal` не рендерится

### Requirement: Поля формы определяются конфигом колонок

Поле SHALL входить в форму, только если колонка не системная и не выключена для этой формы:
`creating: false` исключает поле из формы создания, `editing: false` — из формы редактирования.
`editing: false` не исключает поле из формы создания.

#### Scenario: Колонка только для создания

- **WHEN** у колонки `editing: false` и не задан `creating`
- **THEN** её поле есть в форме создания и отсутствует в форме редактирования

#### Scenario: Системные колонки не попадают в форму

- **WHEN** в гриде включены выбор строк и действия над строкой
- **THEN** в форме нет полей для колонок выбора и действий

### Requirement: Своя форма — это свой FormModal

Слот `FormModal` SHALL получать весь контракт формы: `mode`, `title`, `initialValues`, `row`,
`submit`, `validate`, `onSave`, `onCancel`, `isPending`, `formError`, `errors`, `fields` и `children`
(сгенерированную форму). Своя форма подставляется единственным способом — регистрацией своего
компонента в этот слот (на гриде через `components={{ editing: { FormModal } }}` или для всего
приложения); у `<DataGrid.CreatingModal>` / `<DataGrid.EditingModal>` нет `children`.

#### Scenario: Своя форма вместо диалога кита

- **WHEN** на гриде зарегистрирован свой `FormModal`, и форма создания открыта
- **THEN** рендерится только он, а диалог кита и его поля не рендерятся

#### Scenario: Слот знает, какая форма открыта

- **WHEN** открыта форма редактирования
- **THEN** `FormModal` получает `mode: 'editing'` и сгенерированную форму в `children`

### Requirement: initialValues — значения, с которыми форма открылась

При редактировании `initialValues` SHALL содержать значения строки только для полей формы
редактирования. При создании SHALL содержать засев из `creating.defaultValue` колонок и
`creating.defaultValues` таблицы, где табличный уровень перекрывает колоночный, а ключи,
которые задал табличный уровень, сохраняются, даже если колонки для них нет. Пока форма открыта,
`initialValues` SHALL NOT меняться.

#### Scenario: Редактирование не отдаёт нередактируемые колонки

- **WHEN** открыта форма редактирования строки, у которой колонка `createdAt` объявлена с `editing: false`
- **THEN** в `initialValues` нет ключа `createdAt`

#### Scenario: Значения по умолчанию при создании

- **WHEN** у колонки `status` есть `creating.defaultValue: 'draft'`, а `creating.defaultValues` задаёт `status: 'new'`
- **THEN** `initialValues.status` равен `'new'`

#### Scenario: Ввод не меняет initialValues

- **WHEN** пользователь меняет значение поля в дефолтной форме
- **THEN** `initialValues` остаётся тем же объектом с теми же значениями

### Requirement: row отдаёт исходную строку только для чтения

При редактировании `row` SHALL быть исходным объектом строки (`row.original`) со всеми его полями,
включая поля без колонок. При создании `row` SHALL быть `undefined`. Значения из `row` SHALL NOT
попадать в `values`, которые уходят в сохранение, если форма сама их не передала.

#### Scenario: Своя форма читает id строки

- **WHEN** редактируется строка `{ id: 7, name: 'A', version: 3 }`, а колонка есть только у `name`
- **THEN** `row` равен этому объекту, а `initialValues` равен `{ name: 'A' }`

#### Scenario: row при создании

- **WHEN** открыта форма создания
- **THEN** `row` равен `undefined`

### Requirement: submit со значениями своей формы

`submit(values)` SHALL сохранять переданные значения через пайплайн грида и возвращать результат:
`{ ok: true }` после успешного сохранения или `{ ok: false, reason: 'rejected', errors, formError }` после отказа. Ключи
`values`, которых нет среди полей формы, SHALL доходить до `onSave` без изменений.

#### Scenario: Успешное сохранение своей формы

- **WHEN** своя форма вызывает `submit({ name: 'B', note: 'fixed typo' })` и `onSave` завершается без ошибки
- **THEN** `onSave` получает эти значения, включая `note`, результат равен `{ ok: true }`, а модалка закрывается

#### Scenario: Отказ сервера возвращается в форму

- **WHEN** `onSave` бросает `ValidationError({ errors: { email: ['taken'] } })`
- **THEN** `submit` резолвится в `{ ok: false, reason: 'rejected', errors: { email: ['taken'] }, formError: null }`, модалка остаётся открытой

### Requirement: submit без аргумента сохраняет состояние грида

`submit()` без аргумента SHALL сохранять значения, которые поля дефолтной формы записали в
состояние грида, и возвращать результат той же формы.

#### Scenario: Своя раскладка дефолтных полей

- **WHEN** разработчик рендерит `fields.name` и `fields.email` в своей сетке, пользователь меняет оба поля и вызывается `submit()`
- **THEN** `onSave` получает изменённые значения обоих полей

### Requirement: Ошибки сохранения видны в пропсах слота

После отказа сохранения `errors` и `formError` в пропсах `FormModal` SHALL отражать ошибки
последней попытки, а `isPending` SHALL быть `true`, пока идёт валидация или сохранение.
Повторный `submit` во время сохранения SHALL ничего не делать.

#### Scenario: Двойной клик по сохранению

- **WHEN** `submit` вызван дважды, пока первое сохранение не завершилось
- **THEN** `onSave` вызывается один раз

#### Scenario: Ошибка уровня формы

- **WHEN** валидатор грида вернул `formError: 'Passwords do not match'`
- **THEN** `formError` в пропсах равен этой строке, а `submit` вернул `{ ok: false, reason: 'rejected', formError: 'Passwords do not match', errors: {} }`

### Requirement: fields отдаёт поля дефолтной формы по отдельности

`fields` SHALL содержать по одному отрендеренному полю на каждое поле формы, с ключом `columnId`.
Каждое поле SHALL быть тем же полем, что рендерит дефолтная форма (с подписью, ошибками и
валидацией по `validateOn`), и SHALL писать значения в состояние грида.

#### Scenario: Поле в своей сетке

- **WHEN** разработчик рендерит только `fields.email` внутри своей колонки сетки
- **THEN** поле показывает подпись колонки и ошибки поля `email`, а ввод меняет `email` в состоянии грида

#### Scenario: Поле исключено из формы

- **WHEN** у колонки `creating: false`
- **THEN** в `fields` формы создания нет ключа этой колонки

### Requirement: onCancel закрывает форму

`onCancel()` SHALL закрывать форму, отменять идущие валидацию и сохранение и сбрасывать значения и
ошибки. Результат отменённого сохранения SHALL NOT записываться в состояние.

#### Scenario: Отмена во время сохранения

- **WHEN** `onCancel()` вызван, пока `onSave` ещё выполняется
- **THEN** форма закрыта, а завершение `onSave` не открывает её снова и не пишет ошибки

### Requirement: Слот кита FormModal

Кит SHALL регистрировать слот `FormModal`; его реализация рендерит `children` в своём диалоге и
может игнорировать остальной контракт. Если для `mode: 'modal'` слот не зарегистрирован, грид
SHALL в режиме разработки сообщать об этом ошибкой с именем недостающего слота.

#### Scenario: Кит без слота

- **WHEN** грид с `editing: { mode: 'modal' }` собран с компонентами, где нет `FormModal`
- **THEN** при рендере возникает ошибка, которая называет слот `FormModal`

#### Scenario: Отказ показывается в слоте

- **WHEN** сохранение вернуло `formError`
- **THEN** слот `FormModal` получает этот `formError`, а кнопка сохранения недоступна, пока `isPending`
