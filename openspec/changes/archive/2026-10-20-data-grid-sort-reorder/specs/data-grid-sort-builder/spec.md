# Spec Delta

## Purpose

Определяет билдер мультисортировки data-grid: какие записи он позволяет добавить в соответствии с
конфигом `sorting.multi`, как пользователь меняет приоритет записи и что получает UI-кит, чтобы
нарисовать строку билдера.

## ADDED Requirements

### Requirement: Добавление записи подчиняется multi

Билдер MUST считать мультисортировку включённой только тогда, когда автор написал
`sorting.multi: true` или объект. При выключенной мультисортировке (включая неуказанный `multi`)
`canAddSort` MUST быть `false`, если запись уже есть. При `multi.max` `canAddSort` MUST быть
`false`, когда записей `max`. Вызов `onAddSort` в недоступном состоянии MUST ничего не менять.

Билдер в этом строже заголовка: при неуказанном `multi` TanStack разрешает Shift-клик по
заголовку, и это изменение его не трогает.

#### Scenario: Мультисортировка выключена

- **WHEN** грид с `sorting: {}` отсортирован по одной колонке и открыт билдер
- **THEN** «Add sort» недоступен

#### Scenario: Предел max

- **WHEN** грид с `sorting: { multi: { max: 2 } }` отсортирован по двум колонкам
- **THEN** «Add sort» недоступен
- **AND** после удаления одной записи снова доступен

#### Scenario: Пустая сортировка

- **WHEN** мультисортировка выключена и записей нет
- **THEN** «Add sort» доступен

#### Scenario: Колонка вне мультисортировки

- **WHEN** колонка `notes` объявлена с `sorting: { multi: false }`, а сортировка уже содержит
  другую запись
- **THEN** `notes` нет среди колонок, которые билдер предлагает для второй и следующих записей

### Requirement: Шаг меняет приоритет записи

Когда билдер предлагает шаги, каждая запись MUST получать пару `ordering` с `canMoveStart`,
`canMoveEnd`, `onMoveStart`, `onMoveEnd`, где start — более высокий приоритет. Шаг MUST менять
местами запись и соседнюю, сохраняя направление каждой. У первой записи `canMoveStart` и у
последней `canMoveEnd` MUST быть `false`.

#### Scenario: Поднять запись

- **WHEN** сортировка `[status ↑, date ↓]` и пользователь нажимает шаг вверх у `date`
- **THEN** сортировка становится `[date ↓, status ↑]`
- **AND** `sorting.onChange` вызывается один раз

#### Scenario: Края списка

- **WHEN** в билдере три записи
- **THEN** у первой недоступен шаг вверх, у последней — шаг вниз

#### Scenario: Шаги не предложены

- **WHEN** билдер разрешил режим без шагов
- **THEN** у записей нет поля `ordering`

### Requirement: Перетаскивание меняет приоритет записи

Когда билдер предлагает ручку, запись MUST перетаскиваться за неё на место другой записи. Сброс
MUST переставлять запись в сортировке, сохраняя направления, и коммитить изменение один раз.
Перетаскивание записи MUST NOT менять порядок строк или колонок таблицы и MUST работать с
клавиатуры.

#### Scenario: Перетащить вниз

- **WHEN** сортировка `[a, b, c]` и пользователь тащит `a` за ручку на место `c`
- **THEN** сортировка становится `[b, c, a]`
- **AND** `sorting.onChange` вызывается один раз

#### Scenario: Перетаскивание с клавиатуры

- **WHEN** пользователь берёт ручку записи `Space`, нажимает `ArrowDown` один раз и бросает `Space`
- **THEN** запись сдвигается ровно на одну позицию
- **AND** ни одна другая опция билдера не меняется

#### Scenario: Объявления скринридера

- **WHEN** пользователь берёт, двигает и бросает запись
- **THEN** живой регион объявляет запись сортировки, а не колонку или строку таблицы

### Requirement: Строка билдера в перетаскивании

Пакет MUST предоставлять компонент строки билдера с формой-элементом и формой render-функции,
по образцу строки колоночной панели. Render-функция MUST получать `itemProps` с
`data-slot="sort-row"` (и с `ref`, когда запись участвует в перетаскивании), `handleProps` с `ref`
активатора или `null`, когда запись нельзя перетащить, и `isDragging`.

Перестановка шагом или сбросом MUST NOT опускать ниже первой позиции ещё одну колонку, объявленную
с `sorting: { multi: false }`: такой шаг недоступен, а такой сброс ничего не коммитит.

#### Scenario: Без адаптера

- **WHEN** билдер рендерит строки через render-функцию в гриде без адаптера
- **THEN** `handleProps` равен `null` у каждой записи

#### Scenario: Во время перетаскивания

- **WHEN** пользователь взял запись и ещё не отпустил её
- **THEN** `isDragging` равен `true` только у этой записи

### Requirement: Подписи шагов и ручки

Шаги и ручка записи MUST иметь accessible name из сообщений грида, называющие действие над
записью сортировки. Подписи MUST различаться для разных записей (содержать название колонки
записи), чтобы скринридер не читал список одинаковых кнопок.

#### Scenario: Имя ручки

- **WHEN** запись сортирует по колонке `Status`, а словарь дефолтный
- **THEN** её ручка имеет accessible name, содержащее `Status`
