# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/query-gate/spec.md`.

- TanStack Query в репозитории до этого изменения не используется. Актуальная версия
  `@tanstack/react-query` — 5.105.
- Схемы именования пакетов уже две: `<библиотека>-store` (`zu-store`, `va-store`) различает
  менеджер состояния под одной идеей; `<фича>-core` / `-react` / `-<кит>` (`data-grid-*`,
  `form-*`) различает фреймворк и UI-кит. data-grid построен на TanStack Table и не несёт префикса
  библиотеки.
- [ADR 0001](../../../decisions/0001-no-react-memo.md) запрещает `memo` в data-grid и закрепляет
  изоляцию ре-рендеров через подписки и композицию. На этот пакет запрет формально не
  распространяется, но гейт следует тому же принципу: изоляция достигается тем, что подписка живёт
  внутри гейта, а не мемоизацией.
- Пакеты репозитория: `tsup` (ESM + `.d.ts`), Vitest в jsdom через `vitestPackageConfig`,
  `size-limit` с `ignore` по runtime-зависимостям, `"sideEffects": false`, публичный API только из
  `src/index.ts`. Генератор `pnpm pkg:new` поддерживает расположение `packages/<group>/<name>`.
- В docs-приложении примеры не-data-grid пакетов лежат плоско в
  `apps/docs/shared/examples/<package>/<name>.tsx` и подключаются из MDX по пути; живые примеры
  используют shadcn-компоненты docs-приложения (`@/components/ui/*`).

## Goals / Non-Goals

**Goals:**

- Один компонент и один провайдер, полностью типизированные выводом из `queryOptions`.
- Поведение `<Query>` по каждому состоянию запроса — чистая функция от результата `useQuery`,
  которую можно протестировать без рендера.
- Нулевая собственная терминология поверх TanStack: всё, что приходит из запроса, отдаётся под
  родными именами.

**Non-Goals:**

- Собственный канал доступа к данным под гейтом (контекст, `useData`, scope-фабрики).
- Влияние на сетевое поведение: гейт не меняет `staleTime`, `retry`, `throwOnError` и прочие опции
  запроса.
- Разметка, стили, UI-кит-адаптеры. Примеры на shadcn живут только в docs-приложении.

## Decisions

### D1. Пакет `@ez-kit/query-react` в `packages/query/react` — Durable

Пакет называется по схеме `<фича>-<фреймворк>`, как `data-grid-react` и `form-react`, и лежит в
группе `packages/query/`. Адаптер для другого фреймворка — `query-vue` и т.д. в той же группе.
`query-core` создаётся только тогда, когда у двух адаптеров появится общий код; до этого
фреймворк-независимая логика (D3) — модуль внутри `query-react`.

Отклонено:

- `ta-query` — префикс библиотеки нужен там, где под одной идеей живут несколько библиотек
  (`zu-store` / `va-store`). Второй библиотеки запросов не предвидится, а data-grid на TanStack
  Table уже обходится без префикса.
- `@ez-kit/react-query` — повторяет `@tanstack/react-query` и устаревший пакет `react-query`
  (v3): в автоимпорте и в разговоре «react-query» становится неоднозначным; противоречит схеме
  `<фича>-react`.

### D2. Опции запроса — одним prop `query`, а не spread

`<Query query={deviceQueries.list(f)}>` вместо `<Query {...deviceQueries.list(f)}>` (как у
`@suspensive/react-query`). При spread опции TanStack и props гейта делят одно пространство
имён: новое поле TanStack может столкнуться с `children`, `loading`, `error` или `idle`. Prop
`query` такого риска не несёт, а объект `queryOptions` передаётся как есть, без распаковки.
Отдельного prop `select` нет: он дублировал бы опцию внутри `query`.

### D3. Состояние вычисляется чистой функцией, наличие данных проверяется первым

Внутренний модуль `resolveGateState(result)` возвращает `'data' | 'loading' | 'idle' | 'error'`:

1. `result.data !== undefined` → `'data'` (покрывает фоновое обновление, плейсхолдер и ошибку
   фонового обновления — спека «Данные есть — рендерится children»);
2. `status === 'error'` → `'error'`;
3. `fetchStatus === 'idle'` → `'idle'`;
4. иначе → `'loading'` (`fetching` и `paused`).

Проверка на `undefined` надёжна: в v5 `queryFn` не может вернуть `undefined` — TanStack
считает это ошибкой, поэтому `undefined` в `data` всегда означает «данных нет», а `null` —
полноценные данные. Порядок «данные первыми» — это и есть решение «ошибка при наличии данных
уходит в `children`».

Функция не знает о React и является первым кандидатом в `query-core`, если появится второй
адаптер (D1). Её тестируют таблично, отдельно от рендера.

### D4. Родные имена TanStack, симметричные рендер-функции — Durable

`children(data, q)` и `error(error, q)`, где `q` — результат `useQuery` без изменений. Пакет не
переименовывает поля (`refetch` не становится `retry`) и не выбирает их подмножество: всё, что
нужно рендер-функции, она берёт из `q` под именем из документации TanStack.

Данные под гейтом потомки читают родным `useSuspenseQuery(options)` — это рецепт документации,
а не API пакета. Под гейтом данные уже в кеше, поэтому `useSuspenseQuery` не приостанавливает
рендер, не бросает ошибку при неудачном фоновом обновлении (по умолчанию бросает только без
данных), даёт `data: TData` и за счёт минимального `staleTime` Suspense-режима не запускает
лишний запрос при монтировании потомков.

Отклонено:

- **`Query.useData<T>()` — данные ближайшего гейта через контекст.** Типы держатся на явном
  дженерике, который компилятор не проверяет; вложенный гейт молча перекрывает внешний;
  `select` гейта незаметно меняет форму данных для всех потомков, и их аннотации становятся
  неверными без единой ошибки компиляции. Частичный вывод дженериков в TypeScript невозможен, так
  что `useData<Device>((d) => d.name)` с `TResult = any` даёт молчаливый `any`.
- **`createQueryScope(factory)` — типизированный контекст со scope.** Решает проблемы типов, но
  дублирует то, что уже делает `QueryCache`: глобальное хранилище по ключам с выводом типов из
  `queryOptions`. Вернуться к нему — только с конкретным случаем, где рецепта с
  `useSuspenseQuery` недостаточно.

### D5. Ошибка без фолбека бросается из рендера гейта, а не через `throwOnError`

Если фолбек `error` не найден (D6), гейт выполняет `throw result.error` при рендере. Хук остаётся
в обычном режиме: `throwOnError` гейт не включает.

Почему не `throwOnError`: в этом режиме TanStack сам выключает перезапрос при монтировании после
ошибки, пока не сброшен `QueryErrorResetBoundary`, и пользователю пришлось бы ставить его рядом с
каждым `ErrorBoundary`. При собственном `throw` сброс обычного `ErrorBoundary` перемонтирует гейт,
`retryOnMount` по умолчанию перезапрашивает запрос без данных, и гейт показывает `loading`. Кроме
того, `throwOnError` пробросил бы ошибку и тогда, когда фолбек есть.

Пользователь, явно задавший `retryOnMount: false`, после сброса границы снова получит ту же
ошибку — это выбранное им поведение, его достаточно описать в документации.

### D6. Провайдер сливает фолбеки по ключу с внешним провайдером

`<QueryProvider loading idle error>` кладёт в контекст объект фолбеков, слитый с объектом внешнего
провайдера: каждый заданный ключ перекрывает внешний, незаданный наследуется. Гейт выбирает
каждый фолбек отдельно: prop → контекст → значение по умолчанию (`null` для `loading` и `idle`,
проброс для `error`). Без провайдера контекст пуст, и гейт работает на значениях по умолчанию —
провайдер не обязателен.

Слитый объект мемоизируется по трём входам, чтобы перерисовка провайдера с теми же значениями не
меняла контекст.

Отклонено: конфигурация фолбеков на `QueryClient` (`defaultOptions.meta`) — смешивает
UI-слой с кешем, и `QueryClient` не знает про React-элементы.

### D7. Типы повторяют дженерики `useQuery`

`Query` объявлен с теми же четырьмя параметрами, что `useQuery`:
`<TQueryFnData, TError = DefaultError, TData = TQueryFnData, TQueryKey extends QueryKey = QueryKey>`,
`query: UseQueryOptions<TQueryFnData, TError, TData, TQueryKey>`. Тогда `children` получает
`(data: TData, q: UseQueryResult<TData, TError>)`, а `error` — `(error: TError, q: …)`. Тип ошибки
по умолчанию учитывает `Register` TanStack, то есть глобально объявленный тип ошибки работает и
здесь.

Явных дженериков в месте использования не требуется: всё выводится из `query`. Гарантии типов
проверяются type-тестами (`expectTypeOf` и `@ts-expect-error`), которые компилирует
`pnpm typecheck`.

### D8. Изоляция ре-рендеров без `memo`

`useQuery` вызывается внутри `<Query>`, поэтому подписан на кеш только гейт: родитель и соседи не
получают уведомлений. Рендер-функции вызываются в рендере гейта, отдельного компонента для них
нет. Гарантию держит тест со счётчиками рендеров (по образцу
`data-grid/host-rerender-isolation.test.tsx`): два гейта в одном родителе, обновление одного
запроса, родитель и второй гейт не перерисованы.

`notifyOnChangeProps` по умолчанию отслеживает обращения к полям результата. Гейт сам читает
`data`, `status`, `fetchStatus` и `error`, а остальные поля `q` попадают в отслеживание, только
если рендер-функция их прочитала, — это поведение TanStack, гейт его не меняет.

### D9. Документация и примеры

- Раздел `apps/docs/content/docs/query-react/` со страницами по образцу `twc` / `zu-store`:
  `index` (зачем и быстрый старт), страница про состояния и фолбеки, рецепт «данные под гейтом»,
  `ai.mdx`, `meta.json` с `root: true`.
- Примеры — `apps/docs/shared/examples/query-react/*.tsx` на shadcn-компонентах docs-приложения.
  Каждый пример создаёт свой `QueryClient` (кеш примеров не общий) и использует фейковый
  `queryFn` с задержкой и переключателем ошибки — без сети, чтобы все состояния были
  воспроизводимы на витрине.
- По правилу «нет внутренних комментариев в примерах» пояснения — в MDX, не в коде примеров.
- `content/docs/query-react` добавляется в `SCANNED_ROOTS`, а страницы — в `DocPage` /
  `PAGE_ENTRIES` (`apps/docs/test/docs-options/page-type-map.ts`), чтобы таблицы props
  проверялись по реальным типам.
- `tree-shaking.test.ts` получает кейс пакета: `Query` и `QueryProvider` тянут только сам пакет.

### D10. Зависимости и бюджет

`peerDependencies`: `react >=18.0.0`, `@tanstack/react-query ^5.0.0`. Пакет использует только API
первой мажорной версии v5 (`fetchStatus`, `isPlaceholderData`, типы `UseQueryOptions` /
`UseQueryResult` / `DefaultError` / `QueryKey`). `devDependencies` — актуальная 5.x.
`size-limit` для `dist/index.js` выставляется по реальному размеру плюс ~15%;
`@tanstack/react-query` как peer в бюджет не входит.

## Risks / Trade-offs

- **[Провайдер с JSX-фолбеками перерисовывает все гейты, когда перерисовывается его родитель]**
  JSX-элемент — новый объект на каждый рендер, мемоизация по входам этого не спасёт. → Провайдер
  обычно стоит у корня приложения и перерисовывается редко; в документации — совет выносить
  фолбеки в константы или передавать функции-компоненты.
- **[`children` при ошибке фонового обновления может не заметить ошибку]** Ошибка лежит в
  `q.error`, и рендер-функция, которая её не читает, покажет устаревшие данные без индикации. →
  Это осознанный выбор (ошибка не стирает данные); в документации — пример индикатора по
  `q.isError`.
- **[`useSuspenseQuery` вне гейта и вне `<Suspense>`]** Рецепт D4 безопасен только под гейтом или
  под `<Suspense>`; без них компонент приостановит рендер без границы. → Документация явно
  ограничивает рецепт этими случаями.
- **[Изменения типов TanStack внутри v5]** Peer `^5.0.0` шире, чем проверенная версия. →
  Type-тесты гоняются против devDependency; при поломке на новой минорной сужаем peer-диапазон.

## Migration Plan

Новый пакет, существующих потребителей нет. Первая версия публикуется локальным `pnpm release`
(trusted publisher можно настроить только для существующего пакета), затем на npmjs.com
настраивается trusted publisher для `release.yml`. Перед архивацией изменения решения D1 и D4
оформляются ADR в `openspec/decisions/` с правилами и ссылками в `AGENTS.md`.
