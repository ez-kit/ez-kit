# Spec Delta

## ADDED Requirements

### Requirement: Подпись оператора разрешается из определения, затем из словаря

Подпись оператора MUST быть `label` его определения, если он задан; иначе запись группы словаря
`messages.operators`, которую называет поле `labels` определения; иначе запись
`messages.operators.common` по id. Переключатель, меню, чип и модель фильтра MUST показывать эту
подпись.

#### Scenario: Явная подпись выигрывает у словаря

- **WHEN** набор текстового типа содержит `{ id: 'equals', input: 'single', label: 'Точно', filterFn }`, а словарь задаёт `operators.common.equals` как `Равно`
- **THEN** переключатель оператора колонки показывает `Точно`

#### Scenario: Встроенный оператор без подписи

- **WHEN** у текстовой колонки из готового набора текущий оператор `contains`, а у грида словарь `messages: { operators: { common: { contains: 'Содержит' } } }`
- **THEN** кнопка оператора, пункт меню и чип активного фильтра показывают `Содержит`

#### Scenario: Группа подписей набора

- **WHEN** у колонки типа `date` из готового набора текущий оператор `greaterThan`, а у грида нет `messages`
- **THEN** подпись — `After`, а у `greaterThan` колонки типа `number` — `Greater than`

### Requirement: Подпись группы следует за определением, а не за типом колонки

Группа словаря, из которой берётся подпись, MUST определяться определением оператора, а не типом
ячейки колонки. Определение готового набора MUST сохранять свою группу в наборе любого типа.

#### Scenario: Свой тип ячейки берёт операторы дат

- **WHEN** проект регистрирует тип `datetime` с `operators: { byType: { datetime: defaultOperators.byType.date } }`, а у колонки типа `datetime` текущий оператор `greaterThan`
- **THEN** подпись — `After`, как у колонки типа `date`

#### Scenario: Свой тип ячейки берёт числовые операторы

- **WHEN** проект регистрирует тип `rating` с набором `defaultOperators.byType.number`, а у грида `messages: ruMessages`
- **THEN** `greaterThan` колонки типа `rating` подписан так же, как у колонки типа `number`

### Requirement: Определения готового набора не несут подписи

Определения из `defaultOperators` MUST NOT задавать `label`. Их подписи MUST браться из словаря, так
что английские подписи готового набора существуют только в `defaultMessages`.

#### Scenario: Чтение определения

- **WHEN** потребитель читает `defaultOperators.byType.text[0].label`
- **THEN** значение — `undefined`

### Requirement: Оператор без подписи показывает id

Если у определения нет `label`, а словарь не даёт подписи ни в группе определения, ни в `common`,
грид MUST показывать id оператора и MUST вывести в development одно предупреждение на id.

#### Scenario: Свой оператор без подписи

- **WHEN** набор текстового типа содержит `{ id: 'fuzzy', input: 'single', filterFn }` без `label`
- **THEN** переключатель показывает `fuzzy`, и в development выводится одно предупреждение с id `fuzzy`

## REMOVED Requirements

### Requirement: Подпись оператора берётся из его определения

**Reason**: Подписи встроенных операторов переезжают в словарь `messages.operators`, чтобы грид
переводился одним словарём. `label` определения остаётся и выигрывает у словаря, но перестаёт быть
обязательным и единственным источником.

**Migration**: Переведённый набор (`defaultOperators` с новыми `label`) продолжает работать без
изменений. Проще заменить его словарём: `messages: { operators: { common: { … }, date: { … },
boolean: { … } } }` или готовым `ruMessages`. Код, который читал `label` определения готового набора,
читает подпись из `messages.operators`.
