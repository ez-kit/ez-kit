# Spec Delta

## ADDED Requirements

### Requirement: Набор операторов задаётся бандлом по типу ячейки

Грид MUST брать операторы колонки из опции `operators.byType` — объекта «тип ячейки → список
определений операторов», который передаётся в `createDataGrid` или в любой слой опций. Колонка
типа `T` с включёнными операторами MUST предлагать операторы из `byType[T]` в том же порядке.
Один и тот же id в наборах разных типов MAY иметь разную логику фильтрации.

#### Scenario: Колонка получает набор своего типа

- **WHEN** бандл создан с `operators: { byType: { date: [after, before] } }`, а колонка `createdAt` типа `date` объявлена с `filtering: { operators: true }`
- **THEN** переключатель оператора колонки `createdAt` предлагает ровно `after` и `before`, в этом порядке

#### Scenario: Один id в разных типах

- **WHEN** `byType.text` содержит `equals`, сравнивающий строки без учёта регистра, а `byType.number` — `equals`, сравнивающий числа
- **THEN** фильтр `equals` текстовой колонки сравнивает строки, а числовой — числа

#### Scenario: Свой тип ячейки

- **WHEN** проект регистрирует тип ячейки `rating`, а бандл создан с `operators: { byType: { rating: [atLeast] } }`
- **THEN** колонка типа `rating` с `filtering: { operators: true }` предлагает `atLeast`

### Requirement: Опция операторов ничего не включает

Опция `operators` MUST NOT включать фильтрацию, операторы или любую другую функцию грида.
Операторы колонки включаются только через `filtering.operators` колонки или таблицы.

#### Scenario: Набор без включения

- **WHEN** бандл создан с `operators: { byType: { text: [contains] } }`, а грид не объявляет `filtering.operators` ни на таблице, ни на колонках
- **THEN** ни у одной колонки нет переключателя оператора

### Requirement: Слой опций заменяет набор только названных типов

`operators.byType` MUST задаваться в `createDataGrid`, в `DataGridOptionsProvider` и в конфиге
экземпляра. Верхний слой MUST заменять набор целиком для каждого типа ячейки, который он называет,
и MUST оставлять наборы остальных типов из нижнего слоя.

#### Scenario: Приложение заменяет набор одного типа

- **WHEN** бандл задаёт наборы для `text`, `number` и `date`, а `DataGridOptionsProvider` задаёт `operators: { byType: { date: [onDay] } }`
- **THEN** колонки `date` предлагают только `onDay`, а колонки `text` и `number` — наборы бандла

#### Scenario: Экземпляр важнее провайдера

- **WHEN** провайдер задаёт `byType.text`, а конфиг экземпляра задаёт другой `byType.text`
- **THEN** текстовые колонки этого грида предлагают набор экземпляра

### Requirement: Оператор по умолчанию для типа ячейки

Фильтр колонки MUST открываться с оператором из `filtering.defaultOperator` колонки, иначе из
`operators.defaultByType[тип]`, иначе с первым оператором набора её типа.

#### Scenario: Оператор по умолчанию из бандла

- **WHEN** бандл создан с `operators: { byType: { date: [equals, between] }, defaultByType: { date: 'between' } }`, а у колонки типа `date` нет `defaultOperator`
- **THEN** фильтр колонки открывается с `between`

#### Scenario: Без defaultByType

- **WHEN** `byType.number` начинается с `greaterThan`, а `defaultByType` для `number` не задан
- **THEN** фильтр числовой колонки без `defaultOperator` открывается с `greaterThan`

### Requirement: Строковый id колонки ищется в наборе её типа

Строка в `filtering.operators.items` колонки MUST разрешаться только в оператор с этим id из
набора типа ячейки этой колонки. Определение в `items` MUST использоваться как есть. Строка, которой
нет в наборе типа, MUST давать предупреждение в development и оператор, который пропускает все строки.

#### Scenario: Колонка сужает набор своего типа

- **WHEN** у текстовой колонки `filtering: { operators: { items: ['contains', 'equals'] } }`
- **THEN** колонка предлагает `contains` и `equals` из `byType.text`

#### Scenario: Определение прямо в колонке

- **WHEN** колонка задаёт `items: ['contains', { id: 'fuzzy', input: 'single', label: 'Fuzzy', filterFn }]`
- **THEN** колонка предлагает `contains` из набора типа и `fuzzy` с переданной логикой

#### Scenario: Id из чужого типа

- **WHEN** текстовая колонка задаёт `items: ['between']`, а `byType.text` не содержит `between`
- **THEN** в development выводится предупреждение с id колонки и id оператора, а фильтр `between` этой колонки не отсеивает ни одной строки

### Requirement: Определение оператора объявляет вид значения

Определение оператора MUST задавать `input` — одно из `none`, `single`, `range`, `list`. Значение,
которое получает `filterFn`, MUST иметь форму этого вида: нет значения для `none`, одно значение
для `single`, `{ from?, to? }` для `range`, массив для `list`. Определение без `input` MUST NOT
проходить проверку типов.

#### Scenario: Свой оператор-диапазон

- **WHEN** набор числового типа содержит `{ id: 'notBetween', input: 'range', label: 'Not between', filterFn }`, и пользователь задаёт границы 10 и 20
- **THEN** `filterFn` вызывается со значением `{ from: 10, to: 20 }`

#### Scenario: Свой оператор-список

- **WHEN** набор типа `select` содержит `{ id: 'excludesAny', input: 'list', label: 'Excludes any', filterFn }`, и пользователь выбирает `a` и `b`
- **THEN** `filterFn` вызывается со значением `['a', 'b']`

#### Scenario: Определение без input

- **WHEN** автор пишет определение оператора без поля `input`
- **THEN** проверка типов сообщает об ошибке

### Requirement: Пустое значение не доходит до логики оператора

Грид MUST NOT вызывать `filterFn` оператора с `input`, отличным от `none`, если значение фильтра
пустое: нет значения, пустая строка, пустой массив или диапазон без обеих границ. Такой фильтр MUST
пропускать все строки. `filterFn` оператора с `input: 'none'` MUST вызываться всегда.

#### Scenario: Пустой диапазон

- **WHEN** у колонки задан фильтр `{ operator: 'notBetween', value: {} }`
- **THEN** `filterFn` оператора `notBetween` не вызывается, и все строки проходят фильтр

#### Scenario: Оператор без значения

- **WHEN** у колонки задан фильтр `{ operator: 'isEmpty' }`
- **THEN** `filterFn` оператора `isEmpty` вызывается для каждой строки

### Requirement: Подпись оператора берётся из его определения

Определение оператора MUST задавать `label` строкой. Переключатель, меню, чип активного фильтра и
модель фильтра MUST показывать этот `label` без поиска в словаре грида. Словарь грида MUST NOT
содержать подписей операторов.

#### Scenario: Переведённый набор

- **WHEN** проект передаёт набор, где у `contains` подпись `Содержит`
- **THEN** переключатель оператора, пункт меню и чип активного фильтра показывают `Содержит`

#### Scenario: Подпись не зависит от словаря

- **WHEN** у грида задан словарь `messages`, а в наборе у `greaterThan` типа `date` подпись `After`
- **THEN** у `greaterThan` колонки типа `date` подпись `After`

### Requirement: Готовый набор операторов

Пакет MUST экспортировать из `@ez-kit/data-grid-core/operators` набор `defaultOperators` с
наборами для всех встроенных типов ячеек и константы `FilterOperator` с id этого набора. Внутри
набора один id MUST означать одно сравнение во всех типах; отличаться MAY только подпись.

#### Scenario: Одно сравнение под одним id

- **WHEN** потребитель читает `defaultOperators.byType`
- **THEN** равенство называется `equals` в наборах `text`, `number`, `date` и `boolean`, а «строго больше» — `greaterThan` в `number` и `date`

#### Scenario: Подпись по типу

- **WHEN** у колонки типа `date` из готового набора текущий оператор `greaterThan`
- **THEN** его подпись `After`, а у колонки типа `number` — `Greater than`

#### Scenario: Готовые киты подключают набор

- **WHEN** грид создан готовым `DataGrid` любого кита, а колонка типа `text` объявлена с `filtering: { operators: true }`
- **THEN** колонка предлагает операторы `defaultOperators.byType.text`

#### Scenario: Составной грид не получает набор неявно

- **WHEN** бандл собран через `createDataGrid` без `operators`
- **THEN** у бандла нет ни одного оператора

### Requirement: Импорт констант не тянет готовый набор

Импорт `FilterOperator` или `DEFAULT_OPERATOR_ICONS` из `@ez-kit/data-grid-core/operators` MUST NOT
включать в бандл логику фильтрации готового набора. Импорт `createTable` из
`@ez-kit/data-grid-core` MUST NOT достигать entry `@ez-kit/data-grid-core/operators`.

#### Scenario: Только константы

- **WHEN** приложение импортирует только `FilterOperator` из `@ez-kit/data-grid-core/operators`, и бандл собирается esbuild
- **THEN** в бандле нет `filterFn` операторов готового набора

#### Scenario: Грид без операторов

- **WHEN** приложение импортирует только `createTable` из `@ez-kit/data-grid-core`
- **THEN** бандл не содержит ни одного модуля entry `@ez-kit/data-grid-core/operators`

### Requirement: Включённые операторы без набора

Если `filtering.operators: true` задан на таблице, а у грида нет набора операторов ни для одного
типа ячейки, грид MUST вывести в development одно предупреждение на грид и показать колонкам обычные
фильтры без переключателя. Колонка, которая сама включает операторы, а набора для её типа нет, MUST
давать предупреждение с id этой колонки.

#### Scenario: Составной грид без набора

- **WHEN** бандл собран без `operators`, а грид объявлен с `filtering: { operators: true }` и тремя колонками
- **THEN** в development выводится ровно одно предупреждение, и у всех трёх колонок обычный фильтр без переключателя

#### Scenario: Колонка просит операторы своего типа

- **WHEN** у колонки типа `rating` `filtering: { operators: true }`, а в `byType` нет `rating`
- **THEN** в development выводится предупреждение с id этой колонки и типом `rating`

### Requirement: Неизвестный оператор в значении фильтра

Если значение фильтра колонки называет оператор, которого нет среди операторов колонки (например,
восстановлено из URL), фильтр MUST пропускать все строки, переключатель и чип MUST показывать id
этого оператора, а грид MUST вывести в development одно предупреждение на колонку.

#### Scenario: Ссылка со старым оператором

- **WHEN** грид восстанавливает фильтр `{ operator: 'notBetween', value: { from: 1 } }` для колонки, чей набор не содержит `notBetween`
- **THEN** все строки проходят фильтр, чип показывает `notBetween`, и в development выводится одно предупреждение с id колонки и id оператора

### Requirement: Карта знаков готового набора

Пакет MUST экспортировать из `@ez-kit/data-grid-core/operators` карту `DEFAULT_OPERATOR_ICONS` —
юникод-знак для каждого id готового набора, один для всех типов ячеек. Карта MUST ничего не менять
сама по себе: знак появляется, только если проект перенёс его в поле `icon` определения.

#### Scenario: Знаки набора

- **WHEN** потребитель читает `DEFAULT_OPERATOR_ICONS`
- **THEN** он содержит `contains` `*a*`, `startsWith` `a*`, `endsWith` `*a`, `equals` `=`, `notEquals` `≠`, `greaterThan` `>`, `greaterOrEqual` `≥`, `lessThan` `<`, `lessOrEqual` `≤`, `between` `↔`, `in` `∈`, `notIn` `∉`, `isEmpty` `∅`, `isNotEmpty` `≠∅`

#### Scenario: Знак переносится в определение

- **WHEN** проект собирает набор, где у определения `greaterThan` типа `date` `icon: DEFAULT_OPERATOR_ICONS.greaterThan`, а подпись `After`
- **THEN** кнопка оператора показывает `>`

### Requirement: Иконка оператора задаётся только в определении

Определение оператора MUST принимать необязательное `icon`. В React-адаптере это любое значение,
которое React может отрендерить: строка или элемент. Иконка определения MUST быть единственным
источником иконки оператора.

#### Scenario: Пользовательский оператор со своей иконкой

- **WHEN** колонка предлагает оператор `{ id: 'fuzzy', input: 'single', label: 'Fuzzy', icon: '≈', filterFn }`
- **THEN** при текущем `fuzzy` кнопка оператора показывает `≈`

## MODIFIED Requirements

### Requirement: Встроенные операторы по умолчанию показываются подписью

Оператор готового набора MUST NOT иметь иконки: по умолчанию переключатель показывает подпись
оператора, пока иконку не задали в определении.

#### Scenario: Без настройки знаков нет

- **WHEN** у числовой колонки из готового набора текущий оператор `greaterOrEqual`
- **THEN** кнопка оператора показывает подпись `Greater than or equal`, а не `≥`

## REMOVED Requirements

### Requirement: Реестр таблицы переопределяет встроенный оператор

**Reason**: Табличного реестра `filtering.operators.items` больше нет; операторы задаются набором
бандла по типу ячейки.
**Migration**: Замените оператор в наборе нужного типа: `operators: { byType: { text: [...] } }` в
`createDataGrid`, `DataGridOptionsProvider` или конфиге экземпляра. Чтобы заменить один id в
нескольких типах, замените его в наборе каждого из них.

### Requirement: Подпись переопределённого оператора не локализуется

**Reason**: Подписи операторов больше не берутся из словаря грида, поэтому различать
переопределённые и встроенные операторы не нужно.
**Migration**: Задайте подпись в `label` определения.

### Requirement: Иконки операторов задаются опцией грида

**Reason**: Опция `icons.operators` удалена до выхода в релиз; иконка задаётся только в определении.
**Migration**: Задайте `icon` в определении оператора, например из `DEFAULT_OPERATOR_ICONS`.

### Requirement: Опция иконок проходит через слои опций

**Reason**: Опция `icons.operators` удалена; через слои проходит набор операторов, а иконка входит в
определение.
**Migration**: Передайте набор с иконками в `operators.byType` нужного слоя.

### Requirement: Готовый набор знаков встроенных операторов

**Reason**: Знаки больше не включаются опцией грида; требование заменено на «Карта знаков готового
набора».
**Migration**: Перенесите знак из `DEFAULT_OPERATOR_ICONS` в поле `icon` определения.

### Requirement: Иконку можно задать на операторе

**Reason**: Других источников иконки больше нет, поэтому приоритет между ними не нужен; требование
заменено на «Иконка оператора задаётся только в определении».
**Migration**: Задайте `icon` в определении оператора.
