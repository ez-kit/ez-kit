# Spec Delta

## Purpose

Определяет, откуда колонка `select` / `badge` и поле фильтра берут список значений и подписи:
статический массив или хук потребителя, наследование между ячейкой, фильтром, редактором и
созданием, подпись из самой строки и состояния, которые получает кит.

## ADDED Requirements

### Requirement: Список значений из хука

Колонки `select` и `badge` MUST принимать `cell.config.useItems`: хук, который грид вызывает сам
и который возвращает `{ items, isLoading, error }`. Хук MUST получать объект параметров (сейчас
пустой). Варианты фильтра, редактора и формы создания и подписи ячеек MUST браться из `items`,
которые вернул хук. Колонки при этом создаются один раз, а не на каждый ответ.

#### Scenario: Справочник с бэка без пересоздания колонок

- **WHEN** колонки объявлены на уровне модуля с `cell: { type: 'select', config: { useItems } }`, а хук сначала возвращает `{ items: [], isLoading: true }`, а потом `{ items: [{ value: 'wh_12', label: 'Berlin' }], isLoading: false }`
- **THEN** после ответа ячейка со значением `wh_12` показывает `Berlin`, а колонки не пересоздаются

#### Scenario: Хук получает объект параметров

- **WHEN** грид вызывает `useItems` колонки
- **THEN** хук получает первым аргументом объект

### Requirement: Хук вызывается один раз на источник

Грид MUST вызывать хук каждого источника не больше одного раза на рендер, сколько бы ячеек,
чипов и фильтров его ни читали. Хук MUST вызываться только тогда, когда смонтирован хотя бы один
потребитель его списка, и MUST перестать вызываться, когда потребителей не осталось.

#### Scenario: Сотня ячеек — один вызов

- **WHEN** на странице 100 строк колонки с `useItems`, и все ячейки видимы
- **THEN** хук этой колонки вызывается один раз за рендер грида, а не по разу на ячейку

#### Scenario: Скрытая колонка не запрашивает справочник

- **WHEN** колонка с `useItems` скрыта, её фильтр не смонтирован, и ни один чип и ни одна форма её не показывают
- **THEN** хук этой колонки не вызывается

#### Scenario: Открытый фильтр запускает хук

- **WHEN** колонка скрыта, и пользователь открывает её фильтр в панели фильтров
- **THEN** хук вызывается, и фильтр показывает варианты из его результата

### Requirement: Переопределение списка по месту использования

`filtering`, `editing` и `creating` колонки MUST принимать свои `items` / `useItems`. Редактор MUST
брать `editing`, иначе базу из `cell.config`. Форма создания MUST брать `creating`, иначе `editing`,
иначе базу. Фильтр MUST брать `filtering`, иначе базу. Переопределение MUST менять только
предлагаемые варианты.

#### Scenario: Read-only таблица с одной базой

- **WHEN** колонка `badge` задаёт только `cell.config.useItems`, без `editing` и `filtering`
- **THEN** ячейки подписаны из результата хука, а фильтр предлагает те же варианты

#### Scenario: Создание наследует редактор

- **WHEN** колонка задаёт `cell.config.useItems: useAll` и `editing.useItems: useActive`, а `creating` своего списка не задаёт
- **THEN** форма создания предлагает варианты из `useActive`

#### Scenario: Фильтр со своим списком

- **WHEN** колонка задаёт `cell.config.items` и `filtering.useItems`
- **THEN** фильтр предлагает варианты из `filtering.useItems`, а ячейки подписаны из `cell.config.items`

### Requirement: Подписи берутся из базы

Подпись значения в ячейке, в чипе фильтра и в триггере фильтра или редактора MUST браться из
базового списка (`cell.config`), даже если на этом месте варианты переопределены. Только у колонки
без базового списка подписи MUST браться из списка того места, где значение показано.

#### Scenario: Архивное значение в редакторе с активными вариантами

- **WHEN** база `cell.config.useItems` содержит архивный склад `wh_3` с меткой `Old Depot`, а `editing.useItems` возвращает только активные склады, и пользователь открывает редактор строки со значением `wh_3`
- **THEN** триггер редактора показывает `Old Depot`, а в выпадающем списке `wh_3` нет

#### Scenario: Колонка без базы

- **WHEN** у колонки нет `cell.config.items` и `cell.config.useItems`, но задан `filtering.useItems` с вариантом `{ value: 'eu', label: 'Europe' }`, и выбран фильтр `eu`
- **THEN** чип фильтра показывает `Europe`

### Requirement: Подпись из самой строки

Колонки `select` и `badge` MUST принимать `cell.config.getItem(row)`: элемент, который уже есть в
строке. Значение колонки MUST оставаться тем, что возвращает accessor. Подпись значения в ячейке
MUST браться из базового списка, иначе из `getItem(row)`, иначе MUST показываться pending (пока
список грузится) или сырое значение.

#### Scenario: Подпись видна до ответа справочника

- **WHEN** у колонки задан `useItems`, хук ещё возвращает `isLoading: true`, а `getItem` возвращает `{ value: 'wh_12', label: 'Berlin' }` для строки
- **THEN** ячейка показывает `Berlin` сразу, без состояния загрузки

#### Scenario: Справочник важнее строки

- **WHEN** `getItem` строки возвращает метку `Berlin`, а загруженный справочник отдаёт для `wh_12` метку `Berlin HQ` с иконкой
- **THEN** ячейка показывает `Berlin HQ` с иконкой

#### Scenario: Только getItem, без справочника

- **WHEN** у колонки нет ни `items`, ни `useItems`, а `getItem` возвращает для строки `{ value: 'wh_7', label: 'Bern' }`
- **THEN** ячейка показывает `Bern`

### Requirement: Статус значения для кита

Компонент кита, который показывает значение `select` / `badge`, MUST получать статус: `resolved`
(подпись найдена, вместе с элементом), `pending` (подписи нет, а список грузится), `error` (подписи
нет, а хук вернул ошибку) или `missing` (список загружен, а значения в нём нет). Без асинхронного
источника статус MUST быть `resolved` или `missing`, как сейчас.

#### Scenario: Ожидание справочника

- **WHEN** у колонки задан `useItems` без `getItem`, и хук возвращает `isLoading: true`
- **THEN** компонент ячейки получает статус `pending`

#### Scenario: Ошибка справочника

- **WHEN** хук возвращает `error`, и подписи для значения нет ни в базе, ни в `getItem`
- **THEN** компонент ячейки получает статус `error`, а встроенные ячейки обоих китов показывают сырое значение

#### Scenario: Значения нет в справочнике

- **WHEN** список загружен и не содержит `wh_99`
- **THEN** компонент ячейки со значением `wh_99` получает статус `missing` и показывает `wh_99`

### Requirement: Состояние списка в фильтре и редакторе

Мультивыбор фильтра, select фильтра, редактора и формы создания MUST получать `isLoading` и
`error` того списка, из которого берут варианты. Встроенные компоненты обоих китов MUST показывать
загрузку, пока список грузится, и сообщение об ошибке, если хук вернул ошибку.

#### Scenario: Фильтр во время загрузки

- **WHEN** пользователь открывает фильтр колонки, у которой хук возвращает `isLoading: true`
- **THEN** мультивыбор получает `isLoading: true` и показывает состояние загрузки вместо пустого списка

#### Scenario: Ошибка в редакторе

- **WHEN** хук `editing.useItems` возвращает `error`
- **THEN** select редактора получает этот `error` и показывает его

### Requirement: Поле фильтра со списком из хука

Поле из `filtering.fields` MUST принимать `filtering.useItems` по тем же правилам, что и колонка.
У поля нет строк, поэтому `getItem` и faceted к нему MUST не применяться.

#### Scenario: Поле склада из справочника

- **WHEN** грид объявлен с `filtering: { manual: true, fields: [{ id: 'warehouse', header: 'Склад', cell: 'select', filtering: { useItems } }] }`
- **THEN** фильтр поля `warehouse` предлагает варианты из результата хука

### Requirement: Два источника на одном уровне

Если на одном уровне (`cell.config`, `filtering`, `editing` или `creating`) заданы и `items`, и
`useItems`, грид MUST в режиме разработки предупредить об этом с указанием колонки и уровня и MUST
использовать `useItems`.

#### Scenario: items и useItems в фильтре

- **WHEN** колонка `status` задаёт `filtering: { items: [...], useItems }` в режиме разработки
- **THEN** в консоль выводится предупреждение, которое называет колонку `status` и уровень `filtering`, а фильтр берёт варианты из `useItems`

### Requirement: Нестабильная ссылка на хук

Если ссылка на `useItems` источника меняется между рендерами, грид MUST в режиме разработки
предупредить об этом один раз на источник и назвать колонку. В тексте MUST сказано, что колонки
предупреждения MUST говорить, что колонки нужно объявлять вне компонента или мемоизировать.

#### Scenario: Колонки создаются в теле компонента

- **WHEN** компонент на каждом рендере создаёт колонки с новой inline-функцией `useItems`
- **THEN** в режиме разработки выводится одно предупреждение для этой колонки
