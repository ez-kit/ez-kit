# Proposal

## Why

Список значений колонки (`cell.config.items` у `select` / `badge`, `filtering.items`) сейчас можно
передать только статическим массивом, который фиксируется при создании колонок. Справочник, который
приходит с бэка (склады, теги, пользователи), можно подключить, только пересоздав колонки в
`useMemo` на каждый ответ: так же приходится делать и ради серверных счётчиков faceted. Вдобавок
при серверной пагинации клиентский faceted перезаписывает счётчики любого источника числами,
посчитанными по загруженной странице, а у значения, которого нет в facets, `count` равен
`undefined`, а не `0`.

## What Changes

- Новая опция `useItems`: стабильный хук, который грид вызывает сам и который возвращает
  `{ items, isLoading, error }`. Хук принимает объект параметров, сейчас пустой: `search`, `values`
  и `filters` добавятся позже без поломки. Источник данных, кэш, дедупликацию и инвалидацию держит
  хук потребителя (например, TanStack Query), а грид ничего не кэширует.
- Где задаётся список: база в `cell.config.items` / `cell.config.useItems` у `select` / `badge`,
  переопределения в `filtering`, `editing`, `creating`. Цепочка наследования
  `creating → editing → cell` повторяет `component`, а `filtering` берёт базу, если своего списка
  нет. Переопределение меняет только предлагаемые варианты. Подписи значений всегда берутся из
  базы.
- `items` и `useItems` на одном уровне вызывают предупреждение в dev. Если ссылка на `useItems`
  меняется между рендерами, это тоже предупреждение в dev.
- Хук вызывается один раз на колонку и источник, в runner'е, который монтируется лениво: только
  когда есть хотя бы один потребитель (ячейка, фильтр, чип, редактор). Результат раздаётся
  потребителям через store грида.
- Новая опция `cell.config.getItem(row)`: элемент (`value`, `label`, `icon`, у badge ещё и
  `variant`), который уже есть в самой строке. Значение колонки остаётся скаляром. Подпись
  значения ищется в таком порядке: базовый список, затем `getItem(row)`, затем загрузка, затем
  сырое значение.
- Киты получают статус значения `resolved | pending | missing | error` и сами решают, как его
  нарисовать. Фильтр и редактор получают `isLoading` / `error` для списка вариантов.
- Faceted для клиентских данных подписывает свои значения через `getItem` той строки, из которой
  взято значение. Фильтр получает названия и счётчики без справочника.
- **Изменение поведения:** счётчик `count`, который пришёл из источника (`items` / `useItems`),
  важнее клиентского faceted. Сейчас faceted его перезаписывает.
- **Изменение поведения:** если источник счётчиков есть (faceted или `count` в items), а значения в
  нём нет, вариант получает `count: 0`, а не `undefined`. `undefined` означает «счётчика нет».
- `filtering.faceted` вместе с `filtering.manual: true` вызывает предупреждение в dev: facets
  считаются только по загруженным строкам.
- Поля из `filtering.fields` принимают `filtering.useItems`. У поля нет своих строк, поэтому
  `getItem` и faceted к нему не применяются.

## Capabilities

### New Capabilities

- `data-grid-items-source`: откуда колонка и поле берут список значений и подписи: статические
  `items`, хук `useItems`, наследование между ячейкой, фильтром, редактором и созданием,
  `getItem` из строки, ленивый вызов хука, статусы, которые получает кит, и dev-предупреждения.

### Modified Capabilities

- `data-grid-filter-model`: поле `items` модели строится по новым правилам источника (`useItems`,
  подписи faceted через `getItem`), счётчик источника важнее faceted, отсутствующее значение
  получает `count: 0`, а модель отдаёт состояние загрузки и ошибку списка.

## Impact

- `@ez-kit/data-grid-core`: `SelectCellConfig`, `BadgeCellConfig`, `ColumnFilteringConfig`,
  `ColumnEditingConfig`, `ColumnCreatingConfig`, `FilterFieldDef` получают `useItems` (у cell config
  ещё и `getItem`); типы `ItemsSourceParams`, `ItemsSourceResult`, `ItemStatus`; dev-предупреждения
  в mapper'е и в `createTableOptions`.
- `@ez-kit/data-grid-react`: store источников и ленивый runner, `filter-model.ts`
  (`resolveFilterItems`, `resolveOptionLabel`), `render-filter-input.tsx`, `cell.tsx`,
  `creating-row.tsx`, `auto-form.tsx`, публичный хук для чтения источника колонки.
  Аддитивные необязательные поля в контракте компонентов: `MultiSelectFilterProps.isLoading` /
  `error`, статус значения в `CellViewProps` и `FieldState`.
- Киты shadcn и heroui: `SelectCell`, `BadgeCell` и `MultiSelectFilter` рисуют pending (скелетон),
  error и загрузку списка.
- Документация: страница про асинхронные списки, строки в таблицах опций, `page-type-map.ts`,
  пример с хуком.
- Новых зависимостей нет: TanStack Query нужен только в примерах документации.
- Вне скоупа, следующая фича: `useItems({ search })` и пагинация в выпадающем списке,
  `useItemLabels({ values })` (только в базе, необязательный), `useItems({ filters })` для серверных
  cross-filter facets, документация двух профилей бэкенда («один `/dictionary`» и
  «`?search=` + `?ids=`»). Значения-массивы (например, несколько тегов в одной ячейке) тоже вне
  скоупа: `badge` сейчас однозначный.
