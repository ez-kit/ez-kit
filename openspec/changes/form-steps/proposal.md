# Proposal

## Why

Пошаговую форму сейчас можно собрать только из документа `SchemaForm` (схемный визард). В JSX
есть `withForm`, `withFieldGroup` и `form.FormGroup`, но нет потока шагов: каждое приложение пишет
свой `current` / `goNext` и само решает, что проверять перед «Далее». В D18 спеки 009 этот поток
спроектирован как headless-примитив инстанса, но не реализован — `Steps` и `Step` только
зарезервированы в `reserved-keys.ts` («stage 6»).

Модель M2 (`openspec/specs/form-group-validation`) закрепила, что барьер отправки — схема формы.
Значит, D18 можно реализовать без второго барьера: «Далее» — это сабмит шага, как сабмит группы.

## What Changes

- **`form.Steps` и `form.Step` на каждом инстансе формы**, без вёрстки:
  - `form.Steps` — провайдер со своим стором шагов;
  - части `Steps.List`, `Steps.Item`, `Steps.Controls`, `Steps.Subscribe`;
  - хуки `useStep(name)` и `useSteps(selector, equal?)`.
- **Шаги регистрируются по монтированию** в порядке JSX:
  - условный шаг задаётся через `when`;
  - текущий шаг хранится по `name`;
  - `initial` нужен для SSR, контролируемый режим — `step` / `onStepChange`.
- **Поля и группы регистрируются в шаге по монтированию:** `form.X`, `group.X`, поля записей
  массива, `form.Field`, `form.FormGroup`, `withFieldGroup`. Шаг помнит свой последний список.
- **«Далее» (`goNext`) — сабмит шага.**
  - Поля шага помечаются тронутыми.
  - Синхронно проверяются поля, группы шага, валидаторы шага (по всей форме) и схема формы,
    ограниченная полями шага. Асинхронные валидаторы запускаются, только если синхронные прошли.
  - Вердикт — по ошибкам в полях шага плюс ошибкам шага без пути.
  - Не прошло — фокус на первой ошибке, шаг становится посещённым.
- **Проп `linear`, по умолчанию `true`.**
  - В линейном режиме `goTo` вперёд проверяет текущий шаг. Цель достижима, только если все шаги
    между текущим и ней пройдены и сейчас валидны.
  - При `linear={false}` `goTo` переходит куда угодно без проверки, а «Далее» всё равно проверяет
    шаг и не пускает с ошибками.
  - `goBack` всегда без проверки.
- **Валидаторы `form.Step` работают только на «Далее» и по своим триггерам.** Сабмит формы их не
  запускает (M2): правило, которое держит отправку, живёт в схеме формы.
- **`Steps.Controls` отдаёт `stepErrors` и `formErrors`:**
  - `stepErrors` — ошибки валидатора самого шага без пути;
  - `formErrors` — ошибки схемы формы без пути.

  Ошибки групп без пути показывает сама группа (`group.errors`), в `stepErrors` их нет.

- **Данные пропущенных по `when` шагов остаются в состоянии формы.** Чистый DTO получают через
  `schema.parse(value)` в `onSubmit`: ветка union отбрасывает необъявленные ключи. Утилиты
  `stripSkippedSteps` нет.
- **Если текущий шаг исчезает по `when`,** поток переходит на ближайший видимый шаг назад, а если
  такого нет — на первый видимый.
- **Документация:**
  - новая страница `form/steps.mdx` с примерами для обоих китов: базовый поток, условный шаг с
    union и `parse`, блоки внутри шага, свободный режим, свой степпер на `Steps.Item`;
  - правка D18 в спеке 009 под принятые решения.

## Capabilities

### New Capabilities

- `form-steps`: headless пошаговый поток формы в JSX — регистрация шагов и их полей, навигация и
  её режимы, проверка шага перед переходом, ошибки шага и состояние для степпера.

### Modified Capabilities

## Impact

- `@ez-kit/form-react`: новый модуль шагов (стор, `Steps` и его части, `Step`, хуки), регистрация в
  `field-binding.tsx`, `form-group.tsx` и `map-group.ts`, члены `Steps` / `Step` на инстансе
  (`create-form.tsx`, `build-field-components.tsx`), типы инстанса и `reserved-keys.ts`, экспорты
  хуков и типов из `index.ts`. Валидаторы шага идут на движке проходов map-группы, который для
  этого обобщается.
- `@ez-kit/form-shadcn`, `@ez-kit/form-heroui`: реэкспорт новых хуков и типов. Компоненты кита
  не меняются.
- Документация: `apps/docs/content/docs/form/steps.mdx`, `meta.json`, примеры в
  `apps/docs/shared/form/examples` (manifest, registry), `page-type-map.ts`, e2e для примеров.
- Спека: `specs/009-form-composition/design.md`, раздел D18.
- Релиз: minor-changeset для `@ez-kit/form-react`, `@ez-kit/form-shadcn`, `@ez-kit/form-heroui`.
- Вне рамок:
  - перевод схемного визарда (`schema/form-wizard.tsx`) и `Wizard` кита на этот стор — отдельная
    задача;
  - условный рендер `{cond && <form.Step/>}` (не поддерживается, сказано в доке);
  - синхронизация с URL сверх контролируемого режима.
