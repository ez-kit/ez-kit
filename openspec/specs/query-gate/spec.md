# query-gate Specification

## Purpose

Определяет, как гейт запроса `<Query>` из `@ez-kit/query-react` выбирает, что рендерить, по
состоянию запроса TanStack Query, откуда берёт фолбеки, что передаёт в рендер-функции и какую
изоляцию ре-рендеров гарантирует.

## Requirements

### Requirement: Гейт принимает опции запроса целиком

`<Query>` MUST принимать опции запроса одним prop `query` — тем же объектом, который принимает
`useQuery` (в том числе результат `queryOptions(...)`), и MUST подписываться на этот запрос с этими
опциями без изменений. Опция `select` передаётся внутри `query`; отдельного prop для неё нет.

#### Scenario: Запрос выполняется по переданным опциям

- **WHEN** рендерится `<Query query={queryOptions({ queryKey: ['devices'], queryFn })}>` и кеш пуст
- **THEN** `queryFn` вызывается один раз, а результат кладётся в кеш под ключом `['devices']`

#### Scenario: select внутри query

- **WHEN** `query` содержит `select: (d) => d.items.length`, и запрос завершился успешно
- **THEN** `children` получает результат `select`, а не исходные данные

#### Scenario: Общий кеш с useQuery

- **WHEN** `<Query>` и обычный `useQuery` в другом компоненте используют один `queryKey`
- **THEN** выполняется один сетевой запрос, и оба получают одни и те же данные

### Requirement: Данные есть — рендерится children

Если у запроса есть данные, `<Query>` MUST вызвать `children(data, q)` и отрендерить результат,
где `data` — данные запроса (после `select`), а `q` — результат `useQuery` без изменений. Это
правило действует независимо от `status` и `fetchStatus`: при фоновом обновлении, при
плейсхолдере и при ошибке фонового обновления.

#### Scenario: Успешная загрузка

- **WHEN** запрос завершился успешно с данными `[{ id: 1 }]`
- **THEN** рендерится результат `children([{ id: 1 }], q)`, где `q.status === 'success'`

#### Scenario: Фоновое обновление

- **WHEN** данные уже есть, и запрос перезапрашивается в фоне
- **THEN** рендерится `children` с текущими данными, а `q.isFetching === true`; фолбек `loading`
  не рендерится

#### Scenario: Плейсхолдер

- **WHEN** у запроса нет своих данных, но `placeholderData` вернул значение
- **THEN** рендерится `children` с данными плейсхолдера, а `q.isPlaceholderData === true`

#### Scenario: Ошибка фонового обновления при сохранённых данных

- **WHEN** данные есть, и фоновый перезапрос завершился ошибкой
- **THEN** рендерится `children` с последними данными, а ошибка доступна в `q.error`; фолбек
  `error` не рендерится и ошибка не пробрасывается

### Requirement: Первая загрузка — рендерится loading

Если данных нет, `status` равен `pending`, а `fetchStatus` — `fetching` или `paused`, `<Query>`
MUST отрендерить фолбек `loading`.

#### Scenario: Первая загрузка

- **WHEN** запрос впервые выполняется, и данных в кеше нет
- **THEN** рендерится фолбек `loading`, а `children` не вызывается

#### Scenario: Нет сети до первой загрузки

- **WHEN** данных нет, и запрос приостановлен из-за отсутствия сети (`fetchStatus === 'paused'`)
- **THEN** рендерится фолбек `loading`

### Requirement: Выключенный запрос — рендерится idle

Если данных нет, `status` равен `pending`, а `fetchStatus` — `idle` (запрос выключен через
`enabled: false` или `skipToken`), `<Query>` MUST отрендерить фолбек `idle`, а не `loading`.

#### Scenario: Запрос выключен

- **WHEN** `query` содержит `enabled: false`, и данных в кеше нет
- **THEN** рендерится фолбек `idle`, фолбек `loading` не рендерится, `queryFn` не вызывается

#### Scenario: Запрос включился

- **WHEN** `enabled` меняется с `false` на `true`
- **THEN** рендерится фолбек `loading`, а после успешной загрузки — `children`

### Requirement: Ошибка без данных — рендерится error

Если запрос завершился ошибкой и данных нет, `<Query>` MUST вызвать фолбек `error(error, q)` и
отрендерить результат, где `error` — ошибка запроса, а `q` — результат `useQuery` без изменений.

#### Scenario: Ошибка первой загрузки

- **WHEN** `queryFn` отклонил промис ошибкой `new Error('boom')`, ретраи исчерпаны, данных нет
- **THEN** рендерится результат `error(Error('boom'), q)`, а `children` не вызывается

#### Scenario: Повтор из фолбека

- **WHEN** фолбек ошибки вызывает `q.refetch()`
- **THEN** гейт рендерит `loading`, пока идёт запрос, а затем `children` при успехе или снова
  фолбек `error` при неудаче

### Requirement: Фолбек берётся из prop, затем из провайдера

Для каждого из фолбеков `loading`, `idle` и `error` `<Query>` MUST использовать значение своего
prop, если оно задано, иначе значение ближайшего `<QueryProvider>`, иначе поведение по умолчанию.
Каждый фолбек выбирается отдельно.

#### Scenario: Значение из провайдера

- **WHEN** `<QueryProvider loading={<Spinner />}>` оборачивает `<Query>` без prop `loading`, и
  идёт первая загрузка
- **THEN** рендерится `<Spinner />`

#### Scenario: Prop переопределяет провайдер

- **WHEN** провайдер задаёт `loading={<Spinner />}`, а `<Query>` — `loading={<Skeleton />}`
- **THEN** рендерится `<Skeleton />`

#### Scenario: Фолбеки выбираются независимо

- **WHEN** провайдер задаёт `loading` и `error`, а `<Query>` задаёт только `error`
- **THEN** для загрузки используется `loading` провайдера, а для ошибки — `error` гейта

#### Scenario: Вложенные провайдеры

- **WHEN** внутренний `<QueryProvider>` задаёт только `loading`, а внешний — `loading` и `error`
- **THEN** `<Query>` под ними использует `loading` внутреннего провайдера и `error` внешнего

### Requirement: По умолчанию loading и idle пусты

Если фолбек `loading` или `idle` не задан ни на `<Query>`, ни в провайдере, `<Query>` MUST
отрендерить пустоту (`null`) в соответствующем состоянии.

#### Scenario: Без провайдера и без prop

- **WHEN** `<Query>` без prop `loading` и без провайдера находится в первой загрузке
- **THEN** гейт ничего не рендерит и не бросает ошибку

### Requirement: Ошибка без фолбека пробрасывается

Если запрос в состоянии ошибки без данных, а фолбек `error` не задан ни на `<Query>`, ни в
провайдере, `<Query>` MUST бросить ошибку запроса при рендере, чтобы её поймал ближайший
`ErrorBoundary`. Ошибка MUST NOT быть молча проглочена.

#### Scenario: Проброс к ErrorBoundary

- **WHEN** `<Query>` без фолбека `error` находится под `ErrorBoundary`, и запрос завершился ошибкой
  `Error('boom')` без данных
- **THEN** `ErrorBoundary` получает именно эту ошибку и рендерит свой фолбек

#### Scenario: Повтор после сброса границы

- **WHEN** `ErrorBoundary` сбрасывается и заново монтирует `<Query>` с опциями по умолчанию
- **THEN** запрос перезапрашивается, и гейт рендерит `loading`, а затем `children` или снова
  пробрасывает ошибку

### Requirement: Типы данных и ошибки выводятся из query

Тип первого аргумента `children` MUST быть типом данных запроса после `select`, без `undefined`.
Тип первого аргумента фолбека `error` MUST быть типом ошибки запроса. Второй аргумент обеих
функций MUST иметь тип результата `useQuery` для этих же опций. Явные дженерики при использовании
не требуются.

#### Scenario: data без undefined

- **WHEN** `query` — `queryOptions` с `queryFn: (): Promise<Device[]>`
- **THEN** `children` получает `data` типа `Device[]`, и обращение `data.length` компилируется без
  проверки на `undefined`

#### Scenario: Тип после select

- **WHEN** `query` содержит `select: (d: Device[]) => d.length`
- **THEN** `children` получает `data` типа `number`

### Requirement: Подписка изолирована внутри гейта

Изменения состояния запроса MUST перерисовывать только сам `<Query>` и его рендер-функции.
Родитель `<Query>` и соседние гейты MUST NOT перерисовываться из-за изменения запроса, на который
подписан другой гейт.

#### Scenario: Соседний гейт не перерисовывается

- **WHEN** в одном родителе стоят два `<Query>` с разными запросами, и данные первого запроса
  обновились
- **THEN** первый гейт перерисовывается, а второй гейт и родитель — нет

#### Scenario: Родитель не перерисовывается при загрузке

- **WHEN** запрос `<Query>` проходит путь «загрузка → данные → фоновое обновление»
- **THEN** родитель `<Query>` ни разу не перерисовывается
