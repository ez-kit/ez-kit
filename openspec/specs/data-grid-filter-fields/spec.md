# data-grid-filter-fields Specification

## Purpose

Даёт data-grid фильтруемые поля серверного запроса, которые не являются колонками: их объявляют на
уровне таблицы, редактируют теми же контролами, что и фильтры колонок, а значения уходят на сервер
вместе с фильтрами колонок одним состоянием.

## Requirements

### Requirement: Поля объявляются на уровне таблицы словарём колонки

Грид MUST принимать `filtering.fields` — список полей, каждое с обязательными `id` и `header`
(строка) и необязательными `cell` и `filtering` той же формы, что у колонки. Поле MUST NOT
становиться колонкой: его нет в строках, заголовке, меню видимости, порядке колонок, сортировке и
закреплении.

#### Scenario: Поле не рисуется в таблице

- **WHEN** грид объявлен с колонками `name`, `status` и `filtering: { manual: true, fields: [{ id: 'warehouse', header: 'Склад' }] }`
- **THEN** в заголовке таблицы ровно две колонки, а в меню видимости нет пункта `Склад`

#### Scenario: Поле описано как колонка

- **WHEN** поле объявлено с `cell: { type: 'select', config: { items } }` и `filtering: { operators: true }`
- **THEN** его модель фильтра предлагает операторы типа `select`, а `items` содержит варианты из `cell.config.items`

### Requirement: Поля работают только с серверной фильтрацией

Если `filtering.fields` задан, а `filtering.manual` не равен `true`, грид MUST NOT предлагать поля
ни в одной поверхности фильтров и в режиме разработки MUST предупреждать об этом один раз при
создании таблицы.

#### Scenario: Поля без manual

- **WHEN** в режиме разработки создаётся грид с `filtering: { fields: [{ id: 'warehouse', header: 'Склад' }] }` без `manual`
- **THEN** в консоль выводится предупреждение, называющее `filtering.manual`, а `useFilters()` не содержит цели `warehouse`

#### Scenario: Поля с manual

- **WHEN** создаётся грид с `filtering: { manual: true, fields: [{ id: 'warehouse', header: 'Склад' }] }`
- **THEN** предупреждения нет, а `useFilters()` содержит цель `warehouse`

### Requirement: id поля уникален среди колонок и полей

Создание таблицы MUST завершаться ошибкой, если id поля совпадает с id колонки (включая
системные) или с id другого поля. Сообщение MUST называть совпавший id.

#### Scenario: Совпадение с колонкой

- **WHEN** создаётся грид с колонкой `status` и полем `{ id: 'status', header: 'Статус' }`
- **THEN** создание таблицы бросает ошибку, в тексте которой есть `"status"`

#### Scenario: Совпадение двух полей

- **WHEN** в `filtering.fields` два поля с id `region`
- **THEN** создание таблицы бросает ошибку, в тексте которой есть `"region"`

### Requirement: Значение поля хранится в срезе фильтров колонок

Значение фильтра поля MUST храниться в `columnFilters` записью `{ id, value }` той же формы, что у
колонки, и MUST приходить в `filtering.onChange` в одном массиве с фильтрами колонок. Значение,
заданное через `initialState.columnFilters` или контролируемое состояние, MUST подхватываться полем.

#### Scenario: Поле уходит на сервер вместе с колонками

- **WHEN** пользователь задаёт фильтр колонки `status` и фильтр поля `warehouse`
- **THEN** последний вызов `filtering.onChange` получает массив с записями и `status`, и `warehouse`

#### Scenario: Начальное значение поля

- **WHEN** грид создан с `initialState.columnFilters: [{ id: 'warehouse', value: { operator: 'equals', value: 'msk' } }]`
- **THEN** модель фильтра поля `warehouse` отдаёт это значение, а `hasValue` у его цели равно `true`

### Requirement: Поле в полосе активных фильтров

Полоса активных фильтров MUST показывать чип для заданного фильтра поля с меткой из `header`
поля и сводкой значения, построенной так же, как у колонки. Снятие чипа MUST снимать фильтр поля.

#### Scenario: Чип поля

- **WHEN** у поля `warehouse` с `header: 'Склад'` задан фильтр, и layout рендерит `<DataGrid.ActiveFiltersBar />`
- **THEN** в полосе есть чип с меткой `Склад`

#### Scenario: Снятие чипа поля

- **WHEN** пользователь снимает чип поля `warehouse`
- **THEN** в `columnFilters` нет записи `warehouse`, и `filtering.onChange` получает массив без неё

### Requirement: Поле под отложенным применением

Если у грида включён `draft`, запись фильтра поля MUST попадать в черновик так же, как запись
фильтра колонки, и MUST применяться вместе с ним на `table.draft.apply()`.

#### Scenario: Поле в черновике

- **WHEN** у грида включены `draft` и `filtering: { manual: true, onChange, fields }`, и пользователь задаёт фильтр поля
- **THEN** `onChange` не вызывается, `table.draft.isDirty()` равно `true`, а после `table.draft.apply()` `onChange` получает запись поля

### Requirement: Поле в одиночном фильтре

`<DataGrid.Filter id>` с id поля MUST рендерить фильтр этого поля так же, как для колонки: чип
кита с готовым контролом или, при функции-ребёнке, запись цели фильтра.

#### Scenario: Фильтр поля в тулбаре

- **WHEN** layout рендерит `<DataGrid.Toolbar start={<DataGrid.Filter id='warehouse' />} />`
- **THEN** в тулбаре есть чип `Склад`, открывающий контрол фильтра поля
