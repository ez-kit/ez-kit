title: Reuse sources and factories

Use a **shared collection** when multiple views show the same resource. Use a **shared factory** when different resources follow the same API convention.

## Share one collection between a list and a grid

Start with the collection from [Build an ordinary list](/docs/qc-react/lists). Keep its fetchers, mutation inputs and cache keys in the source. Adapt it once at the grid boundary.

```tsx
import { createGridSourceFromCollection } from '@ez-kit/qc-react/data-grid'
import { useCollectionQuery } from '@ez-kit/query-react/collection'

const dataSource = createGridSourceFromCollection(usersSource, {
	params: ({ pagination, globalFilter }) => ({
		search: typeof globalFilter === 'string' ? globalFilter : '',
		offset: pagination.pageIndex * pagination.pageSize,
		limit: pagination.pageSize,
	}),
	create: ({ values }) => ({ name: values.name ?? '' }),
	update: ({ row, values }) => {
		if (!row) throw new Error('User is no longer available')
		return { id: row.id, name: values.name ?? row.name }
	},
	delete: ({ row }) => ({ id: row.id }),
	deleteMany: ({ rows }) => ({ ids: rows.map((row) => row.id) }),
})

function UsersList() {
	const users = useCollectionQuery({
		source: usersSource,
		mode: 'pages',
		params: { search: '', offset: 0, limit: 2 },
	})
	return (
		<ul>
			{users.items.map((user) => (
				<li key={user.id}>{user.name}</li>
			))}
		</ul>
	)
}

function UsersGrid() {
	return (
		<DataGrid
			dataSource={dataSource}
			columns={columns}
			globalFiltering
			pagination={{ mode: 'pages', pageSize: 2 }}
			editing={{ mode: 'modal' }}
		/>
	)
}
```

Here `DataGrid` comes from `withQuery(gridBundle)`. Render both views under the same `QueryClientProvider`. When their filters and page produce the same query key, they observe the same cache entry. If you move one view to a different page, it gets its own entry. Both entries still belong to the same resource and can refresh after a write.

The grid's `update` mapping takes table context and returns the collection's business input. The collection's own `prepareArgs` then prepares the HTTP argument for its fetcher. An infinite read uses `infiniteParams` for its grid-to-collection parameter mapping.

## Choose a factory for your inputs

Both factories let you share an API convention across resources. Choose based on where read and mutation inputs come from.

- `createCollectionSourceFactory` takes application parameters and business inputs. Use it with `useCollectionQuery` in any list. If a grid also displays those resources, adapt the resulting collection with `createGridSourceFromCollection`.
- `createGridSourceFactory` takes DataGrid's pagination, filtering and sorting state and its row-action contexts. Use it when the source will receive these inputs directly from a connected grid.

### Reuse a factory in ordinary lists

Suppose both the users and teams endpoints take `offset` and `limit` and return `{ items, total }`. Define the argument and response mapping once and give each resource a base key and a fetcher.

```ts
import { createCollectionSourceFactory, useCollectionQuery } from '@ez-kit/query-react/collection'

type ListParams = { offset: number; limit: number }
type NamedRow = { id: string; name: string }
type Page = { items: NamedRow[]; total: number }

const makeCollection = createCollectionSourceFactory({
	list: {
		prepareArgs: (params: ListParams) => params,
		getItems: (page: Page) => page.items,
		getTotal: (page) => page.total,
	},
})

const usersSource = makeCollection({ key: ['users'], getAll: fetchUsers })
const teamsSource = makeCollection({ key: ['teams'], getAll: fetchTeams })

function useTeamList(params: ListParams) {
	return useCollectionQuery({ source: teamsSource, mode: 'pages', params })
}
```

Here `fetchUsers` and `fetchTeams` both accept `ListParams` and return `Promise<Page>`. The lists share the mapping and each has its own cache keys. You can also share infinite read or mutation conventions. See the [collection factory reference](/docs/query-react/collection#reuse-conventions-and-connect-a-grid).

### Reuse a factory in connected grids

For the same endpoints, a grid factory can receive the table's pagination state directly and translate it into the API's offsets.

```ts
import { createGridSourceFactory } from '@ez-kit/qc-react/data-grid'

type NamedRow = { id: string; name: string }
type Page = { items: NamedRow[]; total: number }

const makeSource = createGridSourceFactory({
	list: {
		prepareArgs: ({ pagination }) => ({
			offset: pagination.pageIndex * pagination.pageSize,
			limit: pagination.pageSize,
		}),
		getRows: (page: Page) => page.items,
		getRowCount: (page) => page.total,
	},
})

const users = makeSource({ key: ['users'], getAll: fetchUsers })
const teams = makeSource({
	key: ['teams'],
	getAll: {
		fetcher: fetchTeams,
		options: { staleTime: 30_000 },
	},
})
```

The resources have separate cache keys and reuse the same grid-to-API mapping. Override a read setting when one endpoint needs different behavior.

If you already have OpenAPI, the [Orval recipe](/docs/qc-react/orval) shows how to generate the fetchers and plug them into this pattern.
