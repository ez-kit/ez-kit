title: Paginate a DataGrid
description: Connect numbered pages or infinite scrolling to an API with two interactive examples.
---

Start with the [connected grid](/docs/qc-react). Choose numbered pages when readers need to move between pages and see the total. Choose infinite loading when readers should keep the rows already loaded and request the next portion.

## Numbered pages

### 1. Translate the page into API arguments

Update the list read. DataGrid supplies a zero-based `pageIndex` and the current `pageSize`. The example API accepts `offset`, `limit` and `search`, and returns `{ items, total }`.

```tsx
import { createListSource } from '@ez-kit/qc-react/data-grid'

const getAll = createListSource({
	key: ['users'],
	fetcher: fetchUsers,
	prepareArgs: ({ pagination, globalFilter }) => ({
		offset: pagination.pageIndex * pagination.pageSize,
		limit: pagination.pageSize,
		search: typeof globalFilter === 'string' ? globalFilter : '',
	}),
	getRows: (page) => page.items,
	getRowCount: (page) => page.total,
})

const dataSource = { getAll }
```

For page index 2 and size 10, the offset is 20. For an API with one-based page numbers, use `page: pagination.pageIndex + 1`. The fetcher receives the prepared object and puts its fields where the API expects them.

`getRowCount` gives the grid the total number of matching rows across all pages. If the API omits the total, leave out the getter. A fresh total can also move the grid to the last valid page after deletion.

### 2. Enable pages in the grid

```tsx
<DataGrid
	dataSource={dataSource}
	columns={columns}
	getRowId={(user) => user.id}
	globalFiltering
	pagination={{ mode: 'pages', pageSize: 3 }}
/>
```

The grid owns the current page and resets it to the first page when applied search, filters or sorting change. Map every server-side criterion you enable into `prepareArgs`. TanStack Query caches each distinct set of arguments, so returning to an earlier page can reuse its cached result.

## Infinite scrolling

### 1. Describe the first and next requests

A cursor is the value the API gives you to request the next portion. This example uses a numeric offset as a cursor and receives `{ items, nextCursor }`. An API can also return an opaque string.

```tsx
import { createInfiniteSource } from '@ez-kit/qc-react/data-grid'

type Criteria = { search: string; limit: number }

const getInfinite = createInfiniteSource({
	key: ['users'],
	fetcher: fetchUsers,
	prepareArgs: ({ pageSize, globalFilter }) => ({
		limit: pageSize,
		search: typeof globalFilter === 'string' ? globalFilter : '',
	}),
	preparePageArgs: ({ args, pageParam }: { args: Criteria; pageParam: number }) => ({
		...args,
		offset: pageParam,
	}),
	initialPageParam: 0,
	getRows: (page) => page.items,
	getNextPageParam: (page) => page.nextCursor,
})

const dataSource = { getInfinite }
```

- `prepareArgs` describes the whole collection. The search and page size belong here because changing either starts a new cached collection.
- `preparePageArgs` adds the current cursor to one request. For an API that expects a string field called `cursor`, return `{ ...args, cursor: pageParam }`.
- `initialPageParam` is the first cursor. `getNextPageParam` reads the next cursor from the response and returns `null` or `undefined` at the end.

### 2. Choose a loading trigger

```tsx
<DataGrid
	dataSource={dataSource}
	columns={columns}
	getRowId={(user) => user.id}
	globalFiltering
	pagination={{ mode: 'infinite', pageSize: 3, trigger: 'manual' }}
/>
```

The manual trigger shows a Load more button. To load on scroll, omit `trigger` and give the grid a scroll area, for example with `layout={{ maxHeight: '24rem' }}`. Both triggers use the same cursor mapping.

TanStack Query stores the pages together and the grid renders them as one list. A later-page failure keeps the rows already loaded visible and lets the user retry that page.

## Switch modes in the same grid

Give the source both descriptors when the mode can change at runtime. The source panel in the previews above shows both reads together.

```tsx
const dataSource = { getAll, getInfinite }

// mode comes from the view's 'pages' | 'infinite' preference.
<DataGrid
	dataSource={dataSource}
	columns={columns}
	pagination={{ mode, pageSize: 3 }}
/>
```
