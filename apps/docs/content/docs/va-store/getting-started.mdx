# Getting Started

`@ez-kit/va-store` wraps a [Valtio](https://github.com/pmndrs/valtio) proxy in **React context** so multiple isolated instances of the same state can coexist in one tree, scoped by `Provider`. This page gets you from install to a working store.

## Install

```bash
pnpm add @ez-kit/va-store valtio
```

`valtio` is a **peer dependency** — pin whatever 2.x version your app already uses. Router, storage, and validator integrations used by [Persist](./va-store/persist) are optional peers; install only what you reach for (`react-router`, `next`, `zod`).

## Your first store

`createContextStore(factory)` takes a factory that returns a Valtio proxy and hands back a `Provider` plus hooks. Each `Provider` mount creates its own instance, so two of them never share state.

```tsx
import { createContextStore } from '@ez-kit/va-store'
import { proxy } from 'valtio'

const counterStore = createContextStore(() => {
	const state = proxy({
		count: 0,
		increment: () => {
			state.count += 1
		},
	})
	return state
})
```

## The read/write model

Valtio optimises re-renders per accessed property, so — unlike [`@ez-kit/zu-store`](./zu-store) — there are **no selectors**:

| Action | How                                                                                                       |
| ------ | --------------------------------------------------------------------------------------------------------- |
| Read   | `const snap = store.useSnapshot()` → tracked snapshot; reading `snap.count` subscribes to just that field |
| Write  | `store.useStore().count++` → mutate the raw proxy; snapshots update automatically                         |

`useStore()` returns the **raw mutable proxy** and does not subscribe the component; `useSnapshot()` returns an immutable, render-safe view. Read from snapshots, write to the proxy.

<Callout type='warn'>
	**Breaking change.** `useContextStore()` has been renamed to `useStore()`. Every `@ez-kit` store package now spells
	the raw handle `useStore()`; only the read hook is manager-specific (`useSnapshot()` here). There is still exactly one
	read path and one write path.
</Callout>

## TypeScript & decorators

Plain `createContextStore` needs **no special TypeScript config**. The decorator API used by Persist (`@persistUrl`, `@persistLocalStorage`, …) relies on **Stage 3 (standard) decorators** with `Symbol.metadata` — no `reflect-metadata`, no `experimentalDecorators`:

```jsonc
// tsconfig.json — TypeScript ≥ 5.2
{
	"compilerOptions": {
		"target": "ES2022",
		// Do NOT set experimentalDecorators — Stage 3 is the default and what this package needs.
	},
}
```

<Callout type='info'>
	Prefer no build-time decorator support? The [accessor API](./va-store/persist/fields) is fully equivalent and needs no
	transpilation. Full decorator setup lives in [Persist → TypeScript](./va-store/persist/typescript).
</Callout>
