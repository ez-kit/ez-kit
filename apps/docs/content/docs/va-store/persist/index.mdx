# Persist

Mirror a Valtio store into an external substrate and back, in both directions. Mutating the store writes the substrate; an external change (a deep link, Back/forward, another tab, a restored value) writes the store. The proxy stays **synchronous and snappy** — the substrate is a throttled, rehydratable projection of it.

```bash
pnpm add @ez-kit/va-store valtio
```

Router, storage, and validator integrations are optional peers — install only what you use (`react-router`, `next`, `zod`).

## One engine, many sources

The core never imports React, `URLSearchParams`, or a storage API. Its only interchange language is `Keyed = Map<string, string>` — a logical key mapped to an already-stringified value. A **source adapter** teaches the engine how to read and write one substrate through a small port (`get` / `set` / `subscribe`). Everything else — typed codecs, key naming, throttling, loop-breaking, hydration — is shared.

| Source                        | Import                             | Sync?  |
| ----------------------------- | ---------------------------------- | ------ |
| URL search params             | `@ez-kit/va-store/persist/url`     | sync   |
| localStorage / sessionStorage | `@ez-kit/va-store/persist/storage` | sync   |
| IndexedDB                     | `@ez-kit/va-store/persist/storage` | async  |
| your own                      | a `SourcePort` you write           | either |

Because each source is just an adapter, a single field can sync to **two** substrates at once (a shared `?q=` in the URL _and_ a cached copy in storage), and async sources (IndexedDB) never stall the synchronous URL.

## Mental model

Valtio is the **source of truth**; the substrate is a **mirror**.

- **proxy → substrate**: a `subscribe` watches the store; changed fields are coalesced into one commit per tick (throttled).
- **substrate → proxy**: an external change pushes the diff back into the store, writing only what changed — pulls never re-write the substrate, so Back/forward and other-tab writes are safe.
- **Identity-preserving writes**: fields are addressed by **path** (`filters.price.min`). A pull assigns only the **leaf** — nested objects keep their identity; the engine never replaces a whole subtree.
- **Loop breaking**: each direction writes only when the value differs in normalized form. Parsers carry a round-trip contract so the feedback loop terminates.

## Two ways to declare fields

You bring your own proxy and declare which fields sync. There are two fronts on one engine:

| Front                                                                                    | You write          | Best for                                      |
| ---------------------------------------------------------------------------------------- | ------------------ | --------------------------------------------- |
| [Decorators](./va-store/persist/decorators) — `@persistUrl()` / `@persistLocalStorage()` | classes            | entity models, composition, inheritance       |
| [Fields / accessor](./va-store/persist/fields) — `field(s => s.q, urlField())`           | plain `proxy({…})` | quick stores; no build-time decorator support |

Both produce the same path-based descriptors and feed the same engine, so sources, parsers, and SSR behave identically.
