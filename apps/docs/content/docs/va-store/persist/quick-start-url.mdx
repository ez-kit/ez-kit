# Quick start — URL

The shortest path to URL-as-state: declare which fields sync, mount the URL adapter under a `PersistProvider`, and read/write the store as usual.

<Callout type='warn'>
	The interactive demo is declared with the [accessor API](./fields) so it runs in this in-browser sandbox, and uses an
	isolated in-memory URL adapter so it doesn't hijack this page's address bar. The behavior and URL output match the
	decorator form below exactly.
</Callout>

## The three pieces

```tsx
import { createContextStore, pipe } from '@ez-kit/va-store'
import { PersistProvider, withPersist } from '@ez-kit/va-store/persist'
import { persistUrl } from '@ez-kit/va-store/persist/url'
import { reactRouterAdapter } from '@ez-kit/va-store/persist/url/react-router'
import { proxy } from 'valtio'

// 1. Decorate the fields to sync. Primitives need no parser — it's auto-resolved.
class Filters {
	@persistUrl() q = ''
	@persistUrl() page = 1
}

// 2. Wrap the proxy in `withPersist`. Omit `fields` → decorators are discovered on the instance.
const filtersStore = createContextStore(() => pipe(proxy(new Filters()), withPersist()))

// 3. Mount the URL adapter once, app-level, and render the store under it.
function Page() {
	return (
		<PersistProvider adapters={[reactRouterAdapter]}>
			<filtersStore.Provider>
				<FilterControls />
			</filtersStore.Provider>
		</PersistProvider>
	)
}
```

The `adapters` array is read once and may call hooks (router adapters do), so declare it at module scope or memoize it — keep its length and order stable across renders.

## Read and write

Read with `useSnapshot()`, write through the raw proxy from `useStore()`:

```tsx
function FilterControls() {
	const snap = filtersStore.useSnapshot()
	const store = filtersStore.useStore()
	return (
		<input
			value={snap.q}
			onChange={(event) => {
				store.q = event.target.value // → ?q=…
			}}
		/>
	)
}
```

## Custom URL keys

By default a field's URL key is its property name — `q` becomes `?q=…`. Pass `key` to publish it
under a different one, on either front:

```tsx
class Filters {
	@persistUrl({ key: 'search' }) q = '' // → ?search=…
	@persistUrl() page = 1 // → ?page=…
}
```

```ts
pipe(
	proxy({ q: '', page: 1 }),
	withPersist({
		fields: (field) => [field((s) => s.q, urlField({ key: 'search' })), field((s) => s.page, urlField())],
	}),
)
```

Nothing else changes: the store property stays `q`, only the query string reads `?search=`. This is
the knob for a URL you don't control — a key another page, a legacy link or an analytics tool
already expects.

For a **nested** field the default key is the whole path joined with dots, and `key` renames only
its last segment:

```ts
// state: { filters: { price: { min: 0 } } }
field((s) => s.filters.price.min, urlField()) // → ?filters.price.min=0
field((s) => s.filters.price.min, urlField({ key: 'from' })) // → ?filters.price.from=0
field((s) => s.filters.price.min, urlField({ key: 'from', absolute: true })) // → ?from=0
```

`absolute` drops the ancestor segments entirely, and `prefix` is prepended verbatim
(`urlField({ prefix: 'cart.' })` → `?cart.q=…`) — useful when two stores would otherwise claim the
same key. The full semantics, identical across both fronts, are on
[Decorators → Key placement](./decorators#key-placement).
