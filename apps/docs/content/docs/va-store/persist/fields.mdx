The accessor API is the second front on the same engine: no classes, no build-time decorator support required. Pass a builder that declares each field with a typed selector and a **source** helper; the parser type follows the selected leaf, and you get autocomplete on the store shape.

```tsx
import { createContextStore, pipe } from '@ez-kit/va-store'
import { withPersist } from '@ez-kit/va-store/persist'
import { urlField } from '@ez-kit/va-store/persist/url'
import { localStorageField } from '@ez-kit/va-store/persist/storage'
import { proxy } from 'valtio'

const store = createContextStore(() =>
	pipe(
		proxy({ q: '', page: 1, pageSize: 25 }),
		withPersist({
			fields: (field) => [
				field((s) => s.q, urlField()), // → ?q=
				field((s) => s.page, urlField()), // auto-resolved number
				field((s) => s.pageSize, localStorageField()), // persisted to localStorage
			],
		}),
	),
)
```

The selector supports **direct property access only** (`s => s.a.b.c`) — it's recorded to derive the path, not executed for its value. Each field's second argument is a source helper (`urlField()`, `localStorageField()`, `sessionStorageField()`, `indexedDbField()`), which returns the `{ source, … }` options the field needs.

<Callout type='info'>
	Same engine, two fronts: decorators for [classes](./decorators), `field()` for plain proxies. Pick per project; mix
	per store. Sources, parsers, and SSR behave identically.
</Callout>

## Per-field options

The source helper accepts the same options as the matching decorator — `parser`, `key`, `absolute`, `prefix`:

```tsx
import { paramEnum } from '@ez-kit/va-store/persist'

createContextStore(() =>
	pipe(
		proxy({ filters: { search: { q: '' }, sort: 'asc' as 'asc' | 'desc' } }),
		withPersist({
			fields: (field) => [
				field((s) => s.filters.search.q, urlField({ key: 'q', absolute: true })), // → ?q
				field((s) => s.filters.sort, urlField({ parser: paramEnum(['asc', 'desc']) })),
			],
		}),
	),
)
```

See [Key placement](./decorators#key-placement) for the full semantics — identical across both fronts.

## Multiple sources, one field

List the same field once per source to dual-bind it (URL when present, restored from storage otherwise):

```tsx
pipe(
	proxy({ q: '' }),
	withPersist({
		fields: (field) => [field((s) => s.q, urlField()), field((s) => s.q, localStorageField())],
	}),
)
```

First-present-wins governs cold start — see [Combined](./combined#first-present-wins-on-cold-start).

## Source aliases and validated JSON

A helper can target the effective name from an adapter map, independently of its built-in source name:

```ts
field(
	(state) => state.layout,
	localStorageField({
		source: 'browser',
		parser: paramJson(),
		schema: { validate: (value) => layoutSchema.parse(value) },
	}),
)
```

The decoder may return unknown; the validator returns the typed current layout. The storage, session,
IndexedDB and URL helpers preserve this distinction. Omitting source on a helper retains its existing
built-in name; omitting source on a plain field uses defaultSource. Prefix/absolute are URL projection
options; storage addresses are always scoped by StoreId.

Explicit control handles select exactly the named source, including names such as $persist. Unknown
names are errors. Reset fields refer to persisted state paths, not physical query names or storage keys;
unknown paths fail before any field resets. Typed handles infer object/array paths when state is known.

Typed reset paths also support numeric dictionary and numeric literal keys. For
`widths: Record<number, number>`, a declared field such as `state.widths[12]` resets with
`fields: [['widths', '12']]`; paths use string segments just like runtime property extraction.
Only fields persisted by the selected source may reset.
