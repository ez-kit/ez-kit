# Migrating from `createPersistStore`

Persistence is now a **capability** attached to the proxy itself, not a bespoke store factory. The dedicated `createPersistStore` and `createPersistFields` factories are removed; instead you wrap the proxy in [`withPersist`](../persist) inside [`createContextStore`](../create-context-store)'s factory — or a cached [`createCachedStore`](../cache)'s factory.

**Everything else is unchanged** — `@persistUrl()` / `@persistLocalStorage()` / `@persistField()` decorators, the accessor builder (`urlField()`, `localStorageField()`, …), all codecs, every adapter (`localStorageAdapter`, `indexedDbAdapter`, the URL adapters), `useHydrated`, and the `$url` / `$persist` handles. Only the store factory and the top-level provider move.

<Callout type='info'>
	If you are migrating from a `{ plugins: [persist()] }` option instead — an intermediate shape this package shipped
	briefly — the change is the same one described below: move the wrapping into the factory as `withPersist(proxy(…),
	options)`. See [Capabilities](../../capabilities) for why the option was replaced by a factory-position wrapper.
</Callout>

## The read/write split — one read hook, one write hook

Separate from the plugin move, the store surface is split into exactly one read hook and one write hook. `useSnapshot()` is the only read (auto-tracked, re-renders on the fields you touch); `useStore()` is the only write path (the raw proxy, never subscribes the caller).

Coming from **`0.2.x`**, where the write path was called `useContextStore()`, this is a rename:

```diff
- const state = store.useContextStore()
+ const state = store.useStore()
  state.q = 'next'
```

Coming from **before `0.2.0`**, `useStore()` is once again the write path, so only reads that went through it have to move:

```diff
- const snap = store.useStore()    // if you were reading from it
+ const snap = store.useSnapshot()
```

The rename is what makes the naming uniform across `@ez-kit`: `useStore()` is the raw handle everywhere, and only the read hook is manager-specific — `useSnapshot()` here, `useSelector()` in [`@ez-kit/zu-store`](../../zu-store/create-context-store).

`Subscribe`'s `{ snap, store }` render argument keeps its meaning, and the new [`Store`](../create-context-store) is its write-only counterpart: it hands over the raw proxy without subscribing, so store mutations never re-render it. The same surface applies to cached groups from [`createCachedStore`](../cache). The package is pre-1.0, so this ships as a `minor` bump.

## `createPersistStore` → `createContextStore` + `withPersist`

Decorator stores discovered fields automatically — `withPersist` with no `fields` does the same:

```tsx
// Before
import { createPersistStore } from '@ez-kit/va-store/persist'

const filtersStore = createPersistStore(() => proxy(new Filters()))
```

```tsx
// After
import { createContextStore } from '@ez-kit/va-store'
import { withPersist } from '@ez-kit/va-store/persist'

const filtersStore = createContextStore(() => withPersist(proxy(new Filters())))
```

The returned `{ Provider, useSnapshot, useStore, Subscribe }` shape is identical, so component code that reads `useSnapshot()` and mutates `useStore()` needs no change.

## `createPersistFields` → `withPersist(proxy, { fields })`

The accessor builder moves verbatim into `withPersist`'s `fields` option:

```tsx
// Before
import { createPersistFields } from '@ez-kit/va-store/persist'

const store = createPersistFields(
	() => proxy({ q: '', page: 1 }),
	(field) => [field((s) => s.q, urlField()), field((s) => s.page, urlField())],
)
```

```tsx
// After
import { createContextStore } from '@ez-kit/va-store'
import { withPersist } from '@ez-kit/va-store/persist'

const store = createContextStore(() =>
	withPersist(proxy({ q: '', page: 1 }), {
		fields: (field) => [field((s) => s.q, urlField()), field((s) => s.page, urlField())],
	}),
)
```

## `useHydrated` is now a standalone hook

The store result no longer exposes a `useHydrated()` method. Import the standalone hook and pass it the raw proxy from `useStore()`:

```tsx
// Before
const hydrated = prefsStore.useHydrated()
```

```tsx
// After
import { useHydrated } from '@ez-kit/va-store/persist'

const store = prefsStore.useStore()
const hydrated = useHydrated(store)
```

## Provider: `StoreProvider` over bare `PersistProvider`

A bare `PersistProvider adapters={[…]}` still works for persist-only apps and is unchanged. When you also use the cache (or want one composition root for both), wrap with `StoreProvider` — it mounts the persist engines **and** the cache in the correct order:

```tsx
// Before — persist only
<PersistProvider adapters={[reactRouterAdapter, localStorageAdapter()]}>{children}</PersistProvider>
```

```tsx
// After — persist (+ optional cache) under one root
import { StoreProvider } from '@ez-kit/va-store'
;<StoreProvider
	persist={[reactRouterAdapter, localStorageAdapter()]}
	cache={cache}
>
	{children}
</StoreProvider>
```

Omit `cache` for a persist-only tree (equivalent to `PersistProvider`), or omit `persist` for cache-only. A store that is both cached and persisted is covered in [Cached stores](./cache).

## Summary

| Before                                                              | After                                                                                      |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `createPersistStore(factory)`                                       | `createContextStore(() => withPersist(factory()))`                                         |
| `createPersistFields(factory, fields)`                              | `createContextStore(() => withPersist(factory(), { fields }))`                             |
| `store.useHydrated()`                                               | `useHydrated(store.useStore())`                                                            |
| `store.useContextStore()` (`0.2.x` write path)                      | `store.useStore()`                                                                         |
| `store.useStore()` (read, pre-`0.2.0`)                              | `store.useSnapshot()`                                                                      |
| `<PersistProvider adapters={[…]}>`                                  | `<StoreProvider persist={[…]} cache={cache}>` (or keep `PersistProvider` for persist-only) |
| decorators, accessor builder, codecs, adapters, `$url` / `$persist` | unchanged                                                                                  |
