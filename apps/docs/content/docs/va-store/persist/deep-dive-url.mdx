# Deep dive — URL

The URL source builds a `SourcePort` over a tiny router driver (`read()` / `commit()`). Key naming lives on the descriptor, so the engine's keys _are_ the URL keys — params it doesn't own are preserved untouched.

## History: push vs replace

By default a commit **replaces** the current history entry, so typing in a search box doesn't stack dozens of Back steps. Opt a field into `push` so each change is a distinct, back-button-able entry:

```tsx
import { persistUrl } from '@ez-kit/va-store/persist/url'
import { UrlHistory } from '@ez-kit/va-store/persist/url'

class Wizard {
	@persistUrl({ history: UrlHistory.Push }) step = 'account'
}
```

When several field changes coalesce into one navigation, any `push` in the batch makes the whole navigation a push.

## Key naming

Three source-agnostic options shape a field's substrate key (they apply to storage too):

| Option     | Effect                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| `key`      | Override the leaf segment (defaults to the property name). `@persistUrl({ key: 'query' })` → `?query=` |
| `prefix`   | Prepend a namespace, e.g. a per-widget scope. `@persistUrl({ prefix: 'a.' })` → `?a.q=`                |
| `absolute` | Pin to an exact top-level key, ignoring ancestor path segments (granular URL packing only).            |

Nested state maps to **dotted** keys by path: `price.min` → `?price.min=`. A URL pull assigns only the leaf, so the `price` object keeps its identity.

## Router adapters

A render-scoped adapter turns router hooks into a port. Two ship in the box; both are optional peers.

```tsx
// react-router v6/v7 (BrowserRouter / data routers)
import { reactRouterAdapter } from '@ez-kit/va-store/persist/url/react-router'
;<PersistProvider adapters={[reactRouterAdapter]}>…</PersistProvider>
```

```tsx
// Next.js App Router
import { nextAdapter } from '@ez-kit/va-store/persist/url/next'
;<PersistProvider adapters={[nextAdapter]}>…</PersistProvider>
```

Render-scoped adapters call hooks, so the `adapters` array must be stable in length and order. To target a different router, [write your own adapter](./va-store/persist/custom-adapter#render-scoped-url-adapters).

## Imperative control via `$url`

Each bound source attaches a non-enumerable handle to the proxy. Resolve the `$url` handle with the typed `urlHandle()` accessor — no casts — and run a mutation whose resulting commit carries explicit `meta`, e.g. forcing a one-off `push` regardless of the field's default:

```tsx
import { urlHandle } from '@ez-kit/va-store/persist'
import { UrlHistory } from '@ez-kit/va-store/persist/url'

function next() {
	const store = wizardStore.useStore()
	// `urlHandle(store)` returns the typed handle; its `meta` is checked against UrlMeta.
	urlHandle(store).runWithMeta({ history: UrlHistory.Push }, () => {
		store.step = 'profile'
	})
}
```

Before the provider connects (server render, first paint) the handle is inert — the mutation still runs, just without engine meta.

## SSR

A `createStore` + `persist()` store is request-scoped: each `Provider` mount creates its own proxy, so concurrent requests never share state. The URL source seeds **synchronously** in render, so server HTML reflects the incoming query string and the first client render matches it — no flash, no hydration mismatch. (Storage sources defer to mount; see the [storage deep dive](./va-store/persist/deep-dive-storage).)
