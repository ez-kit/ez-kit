## Route each field to its source

```tsx
import { createContextStore, pipe, StoreProvider } from '@ez-kit/va-store'
import { withPersist } from '@ez-kit/va-store/persist'
import { localStorageAdapter, localStorageField } from '@ez-kit/va-store/persist/storage'
import { urlField } from '@ez-kit/va-store/persist/url'
import { reactRouterAdapter } from '@ez-kit/va-store/persist/url/react-router'
import { BrowserRouter } from 'react-router'
import { proxy } from 'valtio'

type ListState = { q: string; density: 'comfortable' | 'compact' }

const list = createContextStore(
	() =>
		pipe(
			proxy<ListState>({ q: '', density: 'comfortable' }),
			withPersist({
				fields: (field) => [
					field((state) => state.q, urlField()),
					field((state) => state.density, localStorageField()),
				],
			}),
		),
	{ name: 'list' },
)

function Page() {
	return (
		<BrowserRouter>
			<StoreProvider persist={[reactRouterAdapter, localStorageAdapter()]}>
				<list.Provider>
					<ListControls />
				</list.Provider>
			</StoreProvider>
		</BrowserRouter>
	)
}
```

## Bind one field to two sources

```ts
withPersist({
	fields: (field) => [field((state) => state.q, urlField()), field((state) => state.q, localStorageField())],
})
```

Use this when a shared URL should supply the search if it has one, and the browser should supply
a preference if the link does not. Both fields refer to the same property of the same store.

## Check what happens after reload

For the URL + localStorage example above, open a URL with `?q=boots` and set density to
compact. Reload the page. Query state comes from the URL and density comes from browser storage.

For the dual-bound search field, start with a saved browser search. Open a link with a different,
non-default query to seed that value from the URL. Then open the same page without a query and
check that the saved browser search supplies the value. Changing the search writes to both
sources. Each source has its own acknowledgement and error result.

In the live demo, reload this page to check density. Use the real router integration in your app
to check that a copied query URL restores the search too.

## Save and close across sources

```ts
import { flushPersist, persistHandle } from '@ez-kit/va-store/persist'

const results = await flushPersist(store)
if (Object.values(results).every((result) => result.status === 'fulfilled')) close()

// When only one source matters to this action:
await persistHandle(store, 'localStorage').flush()
```

`flushPersist(store)` waits for every source attached to this store, including URL if configured.
The result uses the effective source names, such as the aliases in your provider map.
For a subset, call the named handles and await their results with `Promise.allSettled()`.

## Reload, explicit restore and external changes

- **Reload (F5)** creates a new store and runs automatic restore for each source.
- **Retry one source** with `await persistHandle(store, 'localStorage').restore()`. It preserves the
  priority of local edits on the current store.
- **Apply external updates** with `restore.externalChanges: 'apply'` for sources that publish
  notifications. Ambient sources ignore these updates by default. IndexedDB has no automatic
  cross-tab notification, so use explicit restore to reread it.

To combine browser storage and a server, register them as aliases and assign each field:

```tsx
<StoreProvider persist={{ browser: localStorageAdapter(), server: settingsAdapter }}>
	<settings.Provider>{children}</settings.Provider>
</StoreProvider>
```

```ts
withPersist({
	restore: { sources: { browser: { timeoutMs: null }, server: { timeoutMs: 1500 } } },
	write: { sources: { server: { throttleMs: 300 } } },
	fields: (field) => [
		field((state) => state.density, { source: 'browser' }),
		field((state) => state.layout, { source: 'server' }),
	],
})
```

The browser read has no restore timeout. The server read gets 1.5 seconds and its writes
are throttled independently. `settingsAdapter` implements your backend. Start with the [simulated server](./operations)
or follow the [custom adapter guide](./custom-adapter). If the settings page contains several
store instances, continue to [cache and scope](./cache).
