# Virtualization

For grids with thousands of rows, render only the rows currently in view. Memory usage stays flat; scroll stays buttery.

## Usage

<DataGridDocsExample exampleId='virtualized' />

```tsx
<DataGrid
	data={data} // 10_000+ rows
	columns={columns}
	virtualization={{ row: { estimateSize: 44, overscan: 10 } }}
/>
```

Virtualization is enabled entirely through this option — there is no separate component or prop to set on the body.

When the defaults suit you, a bare `virtualization` prop is shorthand for `virtualization={{ row: true }}`, which uses an `estimateSize` of 50 and an `overscan` of 5.

## Options

| Option                   | Type                                 | Description                                                                                                                    |
| ------------------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `virtualization`         | `boolean \| VirtualizationConfig`    | Master switch. Default off. `true` is shorthand for `{ row: true }`.                                                           |
| `virtualization.row`     | `boolean \| RowVirtualizationConfig` | Row virtualization. `true` uses the defaults below. Column virtualization is not implemented yet.                              |
| `row.estimateSize`       | `number \| (index) => number`        | Estimated row height in px. Default `50`. Pass a function when rows have variable heights.                                     |
| `row.overscan`           | `number`                             | Extra rows rendered above/below the viewport. Default `5`.                                                                     |
| `virtualization.enabled` | `boolean`                            | Explicit off-switch for a config that came from a defaults layer — the settings survive, the feature does not. Default `true`. |

## Notes

- Virtualization is **not free**: rows are absolutely positioned and the body's height is computed at runtime, so anything measuring real row geometry needs care. If your data set is small (≤ 200 rows), leave virtualization off.
- Column sizing works the same virtualized or not — the column width variables are set on the shared `<table>` element in both modes, so [resizing](/docs/data-grid/columns/resizing) needs no extra configuration here.
- The shadcn and HeroUI flavors both honor `virtualization` — toggle the flavor above to see equivalent behavior.
