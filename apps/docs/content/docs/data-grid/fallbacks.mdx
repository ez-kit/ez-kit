---
title: Fallbacks
description: Loading, empty, and no-results states — three slots the grid renders when there's nothing else to show.
---

The grid distinguishes three "nothing to show" states and gives each its own slot:

- **Loading** — while controlled `state.loading.isPending` reports a pending request. A refetch over existing rows uses an overlay instead.
- **Empty** — the data set is genuinely empty (no rows at all).
- **No results** — the data set has rows, but filters/search excluded them all.

## Usage

Fallbacks render automatically whenever the grid has no visible rows. Switch between the states below to preview each slot.

<DataGridDocsExample exampleId='fallbacks' />

```tsx
<DataGrid.LoadingBody />
<DataGrid.EmptyStateRow>
	No orders yet. <button>Create one</button>
</DataGrid.EmptyStateRow>
<DataGrid.NoResultsRow>
	No matching rows. <DataGrid.ClearFiltersButton />
</DataGrid.NoResultsRow>
```

## Loading

Pass `state.loading` (see [Controlled State](/docs/data-grid/state/controlled)) — the grid renders `<LoadingBody />` instead of rows. The slot is a `LoadingState` object, not a boolean: `isPending` is the initial load, `isFetching` a refetch, and `isError` / `error` the last failure.

Name only the fields you have. A list loaded once needs nothing but `isPending`; the flags you leave out read as `false` and `error` as `null`:

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	state={{ loading: { isPending } }}
/>
```

A TanStack Query result carries all four fields, so it passes through whole — `state={{ loading: query }}`. The grid keeps only those four. An SWR response does not: it has `isLoading` and `isValidating` instead, so map them onto `isPending` / `isFetching`. Passed whole, it would never show a loading state, and the grid warns about it in development.

The default loading fallback renders five skeleton rows. Replace it with `fallbacks.loading.component` to supply your own content.

## Pagination refetch overlay

Switch pages below to see the refetch overlay. Each simulated server request takes **1.2 seconds**:
the first load shows skeleton rows, and subsequent page changes keep the previous rows visible
under a semi-transparent overlay with a centered spinner. The new rows replace them when the request finishes.

<DataGridDocsExample exampleId='fallbacks-pagination' />

The grid shows this overlay when `isFetching` is `true`, `isPending` is `false`, and there are
rendered rows. Changing the page does not set loading flags itself: pass your request status through
`state.loading` and retain the previous data while the next page loads. With React Query,
`placeholderData: keepPreviousData` does that:

```tsx
const query = useQuery({
	queryKey: ['orders', pagination.pageIndex, pagination.pageSize],
	queryFn: () => fetchPage(pagination.pageIndex, pagination.pageSize),
	placeholderData: keepPreviousData,
})

<DataGrid
	features={features}
	data={query.data?.rows ?? []}
	columns={columns}
	state={{ pagination, loading: query }}
	pagination={{
		manual: true,
		rowCount: query.data?.rowCount ?? 0,
		onChange: setPagination,
	}}
/>
```

Register `loadingFeature` and `rowPaginationFeature` alongside the structural features when
composing your feature set. The same overlay appears for server-side sorting, filtering, or a
background refresh with existing rows. Client-side pagination switches rows immediately without a request.
See [Server-side Data](/docs/data-grid/state/server-side) for the complete fetching setup.

## Empty vs No results

The grid picks between them automatically and there is no state override: **empty** renders when `data` itself is empty and nothing is loading, **no results** when filters reduce a non-empty data set to zero rows.

What you can configure is each slot, via `fallbacks`. Pass `false` to disable one, or `{ component }` to replace what it renders — `component` takes a `ReactElement` (rendered as-is) or a `ComponentType` (called via `flexRender`):

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	fallbacks={{
		loading: true,
		empty: { component: <p>No orders yet</p> },
		noResults: false,
	}}
/>
```

## Virtualized pagination refetch overlay

This example loads **100 rows per page**, with a 1.2-second simulated request. Scroll down within
the grid, then switch pages: the previous rows stay mounted and the spinner remains centered in
the visible body area, below the sticky header. The overlay does not move with the virtual scroll range.

<DataGridDocsExample exampleId='fallbacks-pagination-virtualized' />

Use the same `state.loading` and `keepPreviousData` setup as above, then enable virtualization:

```tsx
<DataGrid
	features={features}
	data={query.data?.rows ?? []}
	columns={columns}
	virtualization={{ row: { estimateSize: 40, overscan: 3 } }}
	layout={{ maxHeight: '280px', stickyHeader: true }}
	state={{ pagination, loading: query }}
	pagination={{ manual: true, rowCount: query.data?.rowCount ?? 0, onChange: setPagination }}
/>
```
