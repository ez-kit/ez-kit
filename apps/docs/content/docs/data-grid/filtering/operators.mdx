title: Filter Operators
description: Switch the matching strategy per filter — equals, contains, starts with, between, before, after, and custom predicates.
---

Each column can expose a list of operators the user picks from when filtering — `contains`, `equals`, `startsWith`, `greaterThan`, `lessThan`, `between`, and more. Operators are opt-in: a column gets a selector from its own `filtering.operators`, or from the table-wide switch below. The default set is picked from the column's `cell.type`.

## Usage

```ts
const columns = createColumns<Employee>([
	{
		accessorKey: 'name',
		header: 'Name',
		filtering: { operators: { items: ['contains', 'equals', 'startsWith'] }, defaultOperator: 'contains' },
	},
])
```

### The whole table at once

`filtering.operators` on the grid is the same switch one level up:

```tsx
// every filterable column gets the operators its cell type declares
<DataGrid features={features} data={data} columns={columns} filtering={{ operators: true }} />

// no column gets one, whatever the columns say
<DataGrid features={features} data={data} columns={columns} filtering={{ operators: false }} />
```

A column overrides the table in both directions — `filtering: { operators: false }` opts one
column out of a table-wide `true`, and `filtering: { operators: { items: […] } }` narrows what
it offers. Omit the table-level option entirely and the decision stays per column, which is what
the examples below do.

### The operator control

The operator sits first in the filter's row, before the value control, and never on a row of its
own — so a column with operators is exactly as tall as one without, and **Department** above
lines up with the two beside it. It is a button showing the current operator's label, clipped to
its width; pressing it opens a menu of every operator the column offers, the current one checked.
An operator that takes no value — `isEmpty`, `isNotEmpty` — keeps the row: its label stands where
the input would.

The button's accessible name carries the operator, since a clipped label or an icon reads badly
aloud: it comes from `messages.filtering.operatorTrigger`, `Filter operator: Contains` by default.
The menu is named by `messages.filtering.operator`. See [Localization](/docs/data-grid/localization).

### Icons

By default every operator shows its label. A sign alone in a closed control needs a legend to be
read, which is why the grid does not show one unless you ask. Ask with `icons.operators`, a map
from operator id to anything React renders — and `DEFAULT_OPERATOR_ICONS` is a ready set of signs
for the built-ins (`=`, `≠`, `>`, `≥`, `*a*`, `↔`, `∈`, `∅`, …):

```tsx
import { DEFAULT_OPERATOR_ICONS } from '@ez-kit/data-grid-core'
;<DataGrid
	features={features}
	data={data}
	columns={columns}
	filtering={{ operators: true }}
	icons={{ operators: DEFAULT_OPERATOR_ICONS }}
/>
```

<DataGridDocsExample exampleId='filter-operators-icons' />

The button then shows the icon, and each menu entry shows it beside the label. Name only the ids
you want — the rest keep their label — and use your own icons the same way:
`icons: { operators: { greaterOrEqual: <ArrowUpRight />, contains: <TextSearch /> } }`.

`icons` is a top-level option rather than part of `filtering`, because it switches nothing on:
written in a bundle's `createDataGrid({ defaults })` or on a `DataGridOptionsProvider`, it changes
the icons of every grid below and gives none of them filters. The layers merge per id, so an app
that names one icon keeps the kit's others. An `icon` written on an operator's own definition beats
all of them.

### Text operators

Enable the full text operator set with `filtering: { operators: true }`, or pass an explicit `items` list to restrict it — here **Department** offers only `contains`, `equals`, `isEmpty`, and `isNotEmpty`.

### Number operators

Numeric columns (`cell: { type: 'number' }`) expose comparison operators (`equals`, `notEquals`, `greaterThan`, `greaterOrEqual`, `lessThan`, `lessOrEqual`, `between`). Use `defaultOperator` to pick the one selected first — **Salary** defaults to `greaterOrEqual`.

<DataGridDocsExample exampleId='filter-operators-number' />

### Between — inputs

On a number column the `between` operator renders two bound inputs, matching an inclusive numeric range.

<DataGridDocsExample exampleId='filter-operators-between-inputs' />

### Between — slider

Set `betweenOperator: { slider: true, min, max }` for a draggable range control instead of typed bounds. Both bounds are required — a slider over an unknown domain can express nothing, so without them the filter keeps the two fields and warns in development.

<DataGridDocsExample exampleId='filter-operators-between-slider' />

### Date operators

Date columns (`cell: { type: 'date' }`) get date-aware operators (`equals`, `lessThan`, `lessOrEqual`, `greaterThan`, `greaterOrEqual`, `between`) with a calendar picker. Enable them with `filtering: { operators: true }`.

<DataGridDocsExample exampleId='filter-operators-date' />

### Date between

Combine the date operators with `between` to filter rows falling inside a start–end date range. A date
column always renders the same control: a trigger showing the committed range, opening a two-month
range calendar. Every date operator — not just `between` — can be filled from a preset; see
[Date range](/docs/data-grid/filtering/date-range).

## Built-in operators

One vocabulary across cell types: the same id always means the same comparison, and only the
label changes — `greaterThan` reads "Greater than" on a number column and "After" on a date
one. The ids are the `FilterOperator` members; the bare string is equally valid.

| Operator                         | Cell types                                         | Behavior                                                                             |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `contains`                       | text, image, link                                  | substring match (case-insensitive)                                                   |
| `startsWith` / `endsWith`        | text, image, link                                  | prefix / suffix (case-insensitive)                                                   |
| `equals` / `notEquals`           | text, number, date, boolean, image, link, progress | equality, in the column's own terms                                                  |
| `greaterThan` / `lessThan`       | number, progress, date                             | strictly above / below. Labelled "After" / "Before" on date columns                  |
| `greaterOrEqual` / `lessOrEqual` | number, progress, date                             | at or above / below. Labelled "On or after" / "On or before" on date columns         |
| `between`                        | number, progress, date                             | inclusive range                                                                      |
| `in`                             | select, badge                                      | row value is one of a set (see [Multi-value](/docs/data-grid/filtering/multi-value)) |
| `notIn`                          | select, badge                                      | inverse of `in`                                                                      |
| `isEmpty` / `isNotEmpty`         | every built-in except number and progress          | null / undefined / empty string — renders no value input                             |

An id the column does not offer selects nothing in the operator control and dispatches to no
`filterFn`, so the filter would match every row. `createTable` warns about that in development,
for both `defaultOperator` and `operators.items`.

## Custom operators

Inline on the column, when one column needs it:

```ts
filtering: {
	operators: {
		items: ['contains', { id: 'fuzzy', label: 'Fuzzy match', filterFn: fuzzyMatch }],
	},
}
```

Or once on the table, when several do — `filtering.operators.items` is the registry every
column addresses by id:

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	filtering={{ operators: { items: [{ id: 'fuzzy', label: 'Fuzzy match', filterFn: fuzzyMatch }] } }}
/>
// …and in a column: filtering: { operators: { items: ['contains', 'fuzzy'] } }
```

An id listed on a column resolves against its cell type's own operators first, then the
registry — which is why `equals` compares numbers on a number column and dates on a date one.

A table-level definition sharing a built-in id **replaces that built-in in every column that
offers it**: in each cell type's default set (`operators: true`) as well as in a column that names
the id. It replaces it for every cell type at once — register `equals` and text, number, date and
boolean columns all compare through your `filterFn`, so one that must behave per type checks the
value it is given. Its `label` is kept as written: the grid's dictionary does not rename an
operator you replaced.

## `TableOperatorsConfig`

| Option  | Type                  | Description                                                                                                                                                                                                   |
| ------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `items` | `FilterOperatorDef[]` | Custom operators, and replacements for built-ins in every cell type that offers them, addressable by id from any column's `filtering.operators.items`. Writing the object switches operators on, like `true`. |

## `ColumnOperatorsConfig`

| Option            | Type                                        | Description                                                                                                                           |
| ----------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `items`           | `(FilterOperatorId \| FilterOperatorDef)[]` | Operator ids referencing the registry, or inline operator definitions. Omit to use every default operator for the column's cell type. |
| `betweenOperator` | `BetweenOperatorConfig`                     | UI configuration for the `between` operator — see below.                                                                              |

### `BetweenOperatorConfig`

Number-only. Date presets are configured on the column instead, through
[`filtering.presets`](/docs/data-grid/filtering/date-range).

| Option   | Type      | Description                                                                                                                          |
| -------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `slider` | `boolean` | Renders the range as a two-handle slider. Requires both `min` and `max`; without them the filter falls back to two fields and warns. |
| `min`    | `number`  | Lower bound — clamps the fields, and is the slider's floor.                                                                          |
| `max`    | `number`  | Upper bound — clamps the fields, and is the slider's ceiling.                                                                        |

### `FilterOperatorDef`

| Field           | Type                                          | Description                                                                   |
| --------------- | --------------------------------------------- | ----------------------------------------------------------------------------- |
| `id`            | `FilterOperatorId`                            | Operator id, referenced from `items`. A `FilterOperator` member, or your own. |
| `label`         | `string`                                      | Label shown in the operator selector.                                         |
| `icon`          | `ReactNode`                                   | Shown in place of the label. Beats the grid's `icons.operators` for this id.  |
| `requiresInput` | `boolean`                                     | When `false`, no value input is rendered (e.g. `isEmpty`). Default `true`.    |
| `filterFn`      | `(rowValue: unknown, filterValue) => boolean` | Matching predicate.                                                           |

## `GridIcons`

| Option      | Type                                           | Description                                                                                         |
| ----------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `operators` | `Partial<Record<FilterOperatorId, ReactNode>>` | Each operator's icon, by id. Unnamed ids show their label. `DEFAULT_OPERATOR_ICONS` is a ready set. |
