---
title: Active Filters
description: The two surfaces that show what is currently filtered — a strip of removable chips and the Clear-all button — and where a layout puts them.
---

Wherever [the filter controls live](/docs/data-grid/filtering/variants), the grid can show what is
filtered **right now**, apart from the controls themselves: a strip of removable chips, one per
active filter, and a button that clears them all.

Both read the filter state rather than the header, so they are as useful beside inline inputs as
beside a filter panel. The examples below put the controls behind header popovers, where these two
earn their space: the controls are hidden until clicked, so the strip is the only place the applied
filters are readable. With the controls inline in the header, each chip merely repeats the input
right below it.

## Mounting them

There is no option. `<DataGrid.ActiveFiltersBar />` is the strip and
`<DataGrid.ClearFiltersButton />` is the button; writing one is what mounts it, and where you write
it is where it goes.

<DataGridDocsExample exampleId='filter-chips-auto' />

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	filtering
	globalFiltering
>
	<DataGrid.Toolbar
		start={<DataGrid.GlobalFilterInput />}
		end={<DataGrid.ClearFiltersButton />}
	/>
	<DataGrid.ActiveFiltersBar />
	<DataGrid.Table />
	<DataGrid.Pagination />
</DataGrid>
```

The global search term gets a chip of its own, beside the column ones — the strip lists everything
narrowing the table, not just the column filters.

Neither renders while no filter is active — the strip has nothing to list, and the button hides
unless `alwaysShow` — so neither needs a guard of yours around it.

## Above or below the table

Document order decides it: write the strip before `<DataGrid.Table />` or after it.

<DataGridDocsExample exampleId='filter-chips-below' />

```tsx
<DataGrid.Table />
<DataGrid.ActiveFiltersBar position='below' />
```

`position` is not what moves it. It is what the strip reports itself as, through
`data-chip-position`, and it exists because a stylesheet cannot read a JSX position: both kits rule
on `[data-slot='active-filters-bar'][data-chip-position='…']` for the margin above versus below.
Set it to match where you put the strip. Default `'above'`.

## The two are independent

Mount one without the other. Here the chips carry the whole account of what is filtered, and with
nothing else asking for a toolbar, no `<DataGrid.Toolbar>` is written — so no bar renders.

<DataGridDocsExample exampleId='filter-chips-only' />

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	filtering
>
	<DataGrid.ActiveFiltersBar />
	<DataGrid.Table />
	<DataGrid.Pagination />
</DataGrid>
```

## Keeping the button mounted

`alwaysShow` keeps the Clear-all button mounted and disabled with no active filter — worth it when
its appearing and disappearing makes the toolbar jump.

<DataGridDocsExample exampleId='filter-chips-always' />

```tsx
<DataGrid.Toolbar end={<DataGrid.ClearFiltersButton alwaysShow />} />
```

A prop of the button rather than a table option, because it is a question about this one control's
behaviour and nothing else in the grid reads it.

## Labels and order

`ClearFiltersButton` takes its own children as the label. Writing `children` on the toolbar instead
of filling its slots puts the controls in the order you write them:

<DataGridDocsExample exampleId='filter-chips-custom' />

```tsx
<DataGrid.Toolbar>
	<DataGrid.GlobalFilterInput />
	<DataGrid.ClearFiltersButton>Reset</DataGrid.ClearFiltersButton>
</DataGrid.Toolbar>
```

## Props

### `<DataGrid.ActiveFiltersBar />`

| Prop       | Type                 | Description                                                                                                               |
| ---------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `position` | `'above' \| 'below'` | Which way the strip's margin points, stamped as `data-chip-position` for the kit's stylesheet to read. Default `'above'`. |

### `<DataGrid.ClearFiltersButton />`

| Prop         | Type        | Description                                                                |
| ------------ | ----------- | -------------------------------------------------------------------------- |
| `alwaysShow` | `boolean`   | Render the button (disabled) even with no active filters. Default `false`. |
| `children`   | `ReactNode` | The button's label, replacing the default from the message dictionary.     |
