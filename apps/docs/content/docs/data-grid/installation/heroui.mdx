## 1. Install packages

```bash
pnpm add @ez-kit/data-grid-heroui @heroui/react @heroui/styles
```

`@heroui/react` and `@heroui/styles` (v3) are **peer dependencies**, as are `react` and
`react-dom` (18 or 19). HeroUI is peer rather than bundled on purpose: it is built on React
Aria, whose components talk to each other through React context. A second, differently
versioned copy of `@heroui/react` in your tree would create a second set of contexts — and,
since the kit's stylesheet `@import`s `@heroui/styles`, a second copy of HeroUI's entire CSS.
pnpm and npm resolve peers for you; add them explicitly if your package manager does not.

Everything else arrives with the kit. It depends on `@ez-kit/data-grid-react` and
`@ez-kit/data-grid-core` and re-exports their whole surface — every hook, type and constant is
importable from `@ez-kit/data-grid-heroui` itself. Adding those two to your own `package.json`
buys nothing and lets their versions drift out of step with the kit's.

## 2. Import the stylesheet

Pull in the prebuilt CSS once at your app entry:

```ts
import '@ez-kit/data-grid-heroui/styles.css'
```

This stylesheet defines the CSS tokens and `data-*` selectors the HeroUI flavor's components rely on. You can override any of them from your own design tokens — see [Theming](/docs/data-grid/theming).

## 3. Render a grid

The example below is the published surface, locked to HeroUI.

<DataGridDocsExample
	exampleId='base-plain'
	defaultType='heroui'
	lockFlavor
/>

That's it — sort, filter, paginate, and select all work out of the box. Branch out from [Getting Started → Next steps](/docs/data-grid/getting-started#3-next-steps) for the per-capability deep dive.
