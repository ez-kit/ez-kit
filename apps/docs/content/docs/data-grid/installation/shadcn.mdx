description: Install the data grid for a shadcn-based React app — packages, CSS import, and a working minimal example.

This flavor follows the [shadcn registry](https://ui.shadcn.com/docs/registry) model: the CLI
copies the source into your project instead of installing a versioned npm package. You end up
owning the code — free to read, diff, and edit it — the same way you own any other shadcn
component.

## 1. Add the registry item

```bash
npx shadcn@latest add https://ez-kit-docs.vercel.app/r/data-grid.json
```

This requires an existing shadcn project (`npx shadcn init` if you don't have one yet). It copies
`components/data-grid/**` — cells, toolbar, filtering, pagination, editing blocks, and the shadcn
UI primitives they build on — into your project, and adds `@ez-kit/data-grid-react` plus the
kit's other runtime dependencies to your `package.json`.

That is the command you want unless you also want [drag and drop](/docs/data-grid/drag-and-drop).
Drag ships as a second registry item, because it is the one part of the kit that needs a library of
its own (`@dnd-kit`), and a registry item has one dependency list with no way to mark part of it
optional. If you want it, add **that** item instead of the one above:

```bash
npx shadcn@latest add https://ez-kit-docs.vercel.app/r/data-grid-dnd.json
```

It is still one command, not two: the drag item names the grid item as a registry dependency, so
the CLI installs both file sets and both dependency lists in one run. Pick one of the two commands —
the plain one for a grid without drag, the `-dnd` one for a grid with it.

If you already installed before the split, your `package.json` has `@dnd-kit/react` and
`@dnd-kit/dom` in it. Nothing here takes them back out — `shadcn add` has no uninstall, and
re-running the plain command does not remove a dependency it no longer declares. Drop the two
entries yourself if you are not going to drag anything; the split is what spares the **next**
project from acquiring them in the first place.

Then add `@ez-kit/data-grid-core`:

```bash
pnpm add @ez-kit/data-grid-core
```

Every grid takes a [`features`](/docs/data-grid/feature-set) set, and `tableFeatures` and the
feature exports live on `@ez-kit/data-grid-core/features`. That entry point is deliberately not
re-exported through the React adapter — it is separate so that it tree-shakes, and re-exporting it
would anchor the whole feature graph into every consumer's bundle. Pin it to the same version as
the `@ez-kit/data-grid-react` the CLI added.

To pick up a later update, re-run whichever command you installed with, or check what changed first
with `--diff` on that same URL:

```bash
npx shadcn@latest add https://ez-kit-docs.vercel.app/r/data-grid.json --diff
```

```bash
# if you installed the drag item
npx shadcn@latest add https://ez-kit-docs.vercel.app/r/data-grid-dnd.json --diff
```

## 2. Import the stylesheet

Pull in the copied CSS once at your app entry (`app/layout.tsx`, `_app.tsx`, `main.tsx`, etc.) —
adjust the path if your shadcn `components` alias differs from the default:

```ts
import '@/components/data-grid/styles.css'
```

This stylesheet defines the CSS tokens and `data-*` selectors that the flavor's components rely on. You can override any of them from your own design tokens — see [Theming](/docs/data-grid/theming).

## 3. Render a grid

The example below is the published surface, locked to shadcn.

<DataGridDocsExample
	exampleId='base-plain'
	defaultType='shadcn'
	lockFlavor
/>

That's it — sort, filter, paginate, and select all work out of the box. Branch out from [Getting Started → Next steps](/docs/data-grid/getting-started#3-next-steps) for the per-capability deep dive.
