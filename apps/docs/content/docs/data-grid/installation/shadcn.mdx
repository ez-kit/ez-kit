# Install for shadcn

This flavor follows the [shadcn registry](https://ui.shadcn.com/docs/registry) model: the CLI
copies the source into your project instead of installing a versioned npm package. You end up
owning the code — free to read, diff, and edit it — the same way you own any other shadcn
component.

## 1. Add the registry item

```bash
npx shadcn@latest add https://ez-kit-docs.vercel.app/r/data-grid.json
```

This requires an existing shadcn project (`npx shadcn init` if you don't have one yet). It copies
`components/data-grid/**` — cells, toolbar, filtering, pagination, editing blocks, and the shadcn
UI primitives they build on — into your project, and adds `@ez-kit/data-grid-react` plus the
kit's other runtime dependencies to your `package.json`.

To pick up a later update, re-run the same command, or check what changed first with:

```bash
npx shadcn@latest add https://ez-kit-docs.vercel.app/r/data-grid.json --diff
```

## 2. Import the stylesheet

Pull in the copied CSS once at your app entry (`app/layout.tsx`, `_app.tsx`, `main.tsx`, etc.) —
adjust the path if your shadcn `components` alias differs from the default:

```ts
import '@/components/data-grid/styles.css'
```

This stylesheet defines the CSS tokens and `data-*` selectors that the flavor's components rely on. You can override any of them from your own design tokens — see [Theming](./data-grid/theming).

## 3. Render a grid

The example below is the published surface, locked to shadcn.

<DataGridDocsExample
	exampleId='base-plain'
	defaultType='shadcn'
	lockFlavor
/>

That's it — sort, filter, paginate, and select all work out of the box. Branch out from [Getting Started → Next steps](./data-grid/getting-started#3-next-steps) for the per-capability deep dive.
