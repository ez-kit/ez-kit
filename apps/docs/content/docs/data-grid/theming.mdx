The data grid does **not** prescribe a theme. Each UI-kit flavor exposes a styling contract — CSS tokens + the `data-*` attribute surface — and you override it from your own design system.

> This page is reference prose only. There is no embedded example because theming is something you apply at your app's CSS layer, not inside a sandbox. See [Architecture](/docs/data-grid/architecture) for why styling lives in the flavor packages.

## The contract

The shared React package (`@ez-kit/data-grid-react`) emits a stable set of `data-*` attributes on its semantic elements. Flavors target those attributes in CSS. Your app overrides flavor tokens in its own CSS.

Every rule a flavor ships is scoped to one class, so none of it reaches outside a grid: `ez-shadcn-data-grid` or `ez-heroui-data-grid`. The flavor puts that class on the grid's root element and on every popover, menu and dialog the grid opens, and the shared structural rules sit under `ez-data-grid` the same way. Neither stylesheet carries a theme or any global rule — the shadcn flavor reads your app's shadcn tokens, the HeroUI flavor reads your app's `@heroui/styles`.

The grid's own tokens are declared on that class, so override them there rather than on `:root`:

```css
/* in your app's CSS, after importing the flavor's styles.css */
.ez-shadcn-data-grid {
	--dg-pin-shadow-color: oklch(0 0 0 / 0.2);
	--dg-pin-cell-background: var(--card);
}
```

## Rules

- Don't add CSS to the shared React package — it would force every flavor to fight defaults.
- Avoid `!important` on flavor tokens unless your design system requires it.
