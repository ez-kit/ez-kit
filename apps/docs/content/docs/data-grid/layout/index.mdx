`layout` is where the table's own shape is configured: how tall it may grow, and what stays in view
once its body starts scrolling.

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	layout={{ maxHeight: '32rem', stickyHeader: true, stickyFooter: true }}
/>
```

| Option                      | Type               | Description                                                                                                            |
| --------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `layout.maxHeight`          | `string \| number` | Bounds the scroll container. Omitted, the structural stylesheet's `400px` applies (`600px` when virtualization is on). |
| `layout.stickyHeader`       | `boolean`          | Keeps the header row at the top of the scroll container.                                                               |
| `layout.stickyFooter`       | `boolean`          | The same at the bottom edge, for a totals row — see [Footer](/docs/data-grid/layout/footer).                           |
| `layout.classNames.wrapper` | `string`           | Class for the outer box, outside the scrollport — where a border, radius or shadow belongs.                            |
| `layout.classNames.scroll`  | `string`           | Class for the scrollport itself.                                                                                       |

## Framing the shell

The grid shell is the one part of the table this package renders itself: an outer wrapper, and the
scrollport inside it. Everything the table renders below that — the table element, header, rows,
cells — comes from the kit and sits _inside_ the scrollport.

A kit that ships a stylesheet can already reach both boxes with a `[data-slot='table-scroll']`
rule, and the shadcn kit frames the grid exactly that way. `layout.classNames` is for what a
stylesheet cannot do: class **one** grid rather than every grid, from the call site.

Typically the kit states the frame once:

```tsx
export const { DataGrid } = createDataGrid({
	components,
	defaults: { layout: { classNames: { wrapper: 'rounded-md border' } } },
})
```

and a grid adds to it where it needs to:

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	layout={{ classNames: { wrapper: 'shadow-lg' } }}
/>
```

Classes **accumulate** — unlike every other option, where the higher layer replaces the lower one.
The wrapper above ends up with `rounded-md border shadow-lg`, in that order. Nothing de-conflicts
them: this package emits no styling and knows nothing about Tailwind, so if you need `border-0` to
beat the kit's `border`, run your own value through `cn()` / `twMerge` before passing it.

Class only: positioning, overflow and the height custom properties stay in the structural
stylesheet, and the look stays with the kit.

Which box to use: the **wrapper** is the outer one — a shadow the scrollport would clip, or a frame
that has to enclose the pin-shadow overlay, belongs there. The **scroll** box is the scroller
itself; a border or radius on it is stable, because a scroll container's own border does not move
with its content.

## Sticky header

For tall tables, keep the header row pinned to the top of the scroll container while the body scrolls.

<DataGridDocsExample exampleId='base-sticky' />

```tsx
<DataGrid
	features={features}
	data={data}
	columns={columns}
	layout={{ stickyHeader: true, maxHeight: '32rem' }}
/>
```

`layout.maxHeight` bounds the scroll container — without a bound there is nothing for the header
to stick against. Omit it and the structural stylesheet's `400px` default applies.

`<DataGrid.Header />` reads `layout.stickyHeader` on its own, so a custom
[composition](/docs/data-grid/layout/composition) keeps the sticky header with no extra wiring. Its `sticky` prop
overrides the grid option for one header — useful when a hand-built `<DataGrid.Table>` body holds
more than one.

`layout.stickyFooter` is the same thing at the other edge, for a totals row that has to stay in
view — see [Footer](/docs/data-grid/layout/footer).

## Notes

- The "stickiness" is CSS — `position: sticky` on the `<thead>`. The grid sets `data-sticky="true"` on the header; flavor CSS handles the rest.
- Combine with [Row pinning](/docs/data-grid/pinning/rows) for sticky top rows beneath the header.
- Inside a virtualized body, sticky header still works — the scroll container is the same.
