# Selection Bar

When at least one row is selected, render an action bar that operates on the selection set.

## Floating

A bar floats at the bottom of the table while a selection is active:

<DataGridDocsExample exampleId='selection-bar' />

```tsx
<DataGrid.SelectionBar>
	{({ count, onDelete, onClear }) => (
		<>
			<span>{count} selected</span>
			{onDelete && <button onClick={onDelete}>Delete</button>}
			<button onClick={onClear}>Cancel</button>
		</>
	)}
</DataGrid.SelectionBar>
```

`onDelete` already encodes the confirmation protocol: with a prompt configured it stages the
delete and opens the dialog, without one it deletes immediately. Reaching for your own handler
instead silently skips the prompt.

## Inline

The same content can be rendered inline above the table — no portal, no z-index gymnastics:

<DataGridDocsExample exampleId='selection-bar-inline' />

```tsx
selection: {
	bar: { variant: 'inline' },
}
```

## Custom actions

`selection.bar.actions` builds the entries the bar offers for the selection. It is **data**, not
markup — the same `ActionItem` shape [`rowActions.actions`](./data-grid/row-actions) takes — so the
kit draws each entry with the chrome its own Delete button has: your icon from the built-in set (or
your own element), the kit's danger colour for `destructive`, its disabled state for `disabled`.

```tsx
// One action, offered in both places, written once.
const exportAction = (rows: Row<Product>[]) => ({
	id: 'export',
	label: 'Export',
	icon: 'edit',
	onSelect: () => exportRows(rows),
})

rowActions: { actions: ({ row }) => [exportAction([row])] },
selection: {
	bar: { actions: ({ selectedRows }) => [exportAction(selectedRows)] },
}
```

An entry's `onSelect` takes no arguments: the callback that built it already closes over
`selectedRows`, `table` and `clearSelection`. Return `[]` for a selection that offers nothing.

## Slots

Content that is not an action — a bulk-target select, a counter — goes in the `start` / `end` slots
of `<DataGrid.SelectionBar>`, rendered around the kit's own controls. Same split as
[`<DataGrid.Toolbar>`](./data-grid/toolbar): the config carries data, the compound component
carries markup, and `children` still replaces the bar wholesale.

```tsx
<DataGrid.SelectionBar end={<WarehousePicker />} />
```

## The Delete button

The bar's Delete button is **not** configured here. Bulk delete is the `deleting` feature
operating on more than one row, so its handler and its prompt live next to the per-row ones — see
[Delete confirmation](./data-grid/editing/delete-confirmation). The bar renders the button
whenever `deleting.bulk` resolves to on.

```tsx
deleting: {
	onDelete: ({ row }) => remove(row.original.id),
	// One word: with no handler of its own, bulk delete loops `onDelete` over the selection.
	bulk: true,
}
```

```tsx
deleting: {
	onDelete: ({ row }) => remove(row.original.id),
	bulk: {
		// One call for the whole set — what a "delete these ids" endpoint wants.
		onDelete: ({ rowIds }) => api.removeMany(rowIds),
		confirmation: { title: 'Delete selected products?' },
	},
}
```

The deleted ids leave the selection once the handler resolves, so the bar never counts rows that
no longer exist.

## Options

The bar is configured under `selection.bar` — `true` for the default bar, `'inline'` / `'floating'`
for nothing but the render mode, or an object with the keys below. It renders only while
`selection` is enabled. Everything here is presentational.

| `selection.bar` key | Type                                                | Description                                                                                       |
| ------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `variant`           | `'floating' \| 'inline'`                            | Default `'floating'`.                                                                             |
| `clear`             | `({ table, selectedRows, clearSelection }) => void` | Replaces the default clear behaviour (not a notification — call `clearSelection` to still reset). |
| `actions`           | `(args) => ActionItem[]`                            | Custom entries rendered between Delete and Cancel. See [Custom actions](#custom-actions).         |
