The React adapter sits between [core](/docs/data-grid/advanced/core) and the UI-kit flavors. It exposes hooks, context, and **semantic render slots** — no styling.

> This page is contributor-level. Most app authors should install a flavor instead (see [Getting Started](/docs/data-grid/getting-started)).

## Public surface (overview)

| Export                                                           | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useDataGrid(config)`                                            | The single React entry point. Resolves the config through core's `createTableOptions` and drives TanStack's `useTable`. Takes the [`features`](/docs/data-grid/feature-set) set like every other entry point.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `createColumns<TRow>(defs)`                                      | Typed column array helper.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `createColumnHelper<TRow>()`                                     | Typed column **builder** (see [Column Helper](/docs/data-grid/columns/column-helper)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `CellTypeDefinition` (type), `CellTypesProvider`, `useCellTypes` | The typed contract and context custom cell-type registries are built on. Registration itself (`extendDataGrid()`) is a UI-kit export, not part of this package (see [Custom Cell Types](/docs/data-grid/columns/custom-cell-types)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `createDataGrid({ components, cellTypes, defaults })`            | **Inject a UI-kit's components**, optional cell types, and optional kit-level [default options](/docs/data-grid/state/defaults). Returns a bundle — `DataGrid`, `useDataGrid`, `createColumns`, `createColumnHelper`, `extendDataGrid`, … — bound to them. Flavor packages call it exactly once at module scope.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `DataGrid.*`                                                     | The compound render slots — `Toolbar`, `Table`, `Footer`, `FooterRow`, `FooterCell`, `Header`, `HeaderRow`, `HeaderCell`, `Body`, `Row`, `Cell`, `Pagination`, `PageSizer`, `ColumnFilter`, `ActionBar`, `CreateTrigger`, `VisibilityTrigger`, `SortMenuTrigger`, `GlobalFilterInput`, `ActiveFiltersBar`, `ClearFiltersButton`, `FilterPanel`, `CreatingModal`, `EditingModal`, `LoadingBody`, `EmptyStateRow`, `NoResultsRow`. Every one takes `children` — a node, or a render function receiving that slot's model — and exports a `DataGrid<Name>Props` type. Beside them sit `BottomBar`, and `HeaderMain` / `HeaderExtras`, the header cell's two boxes: plain hosts stamped with their `data-slot`, so a composed header never hand-writes the element the kit's CSS selects on. Their props are `HeaderMainProps` / `HeaderExtrasProps` — `div` attributes, passed straight through. |
| `DataGridRoot`, `DataGridToolbar`, `DataGridTable`, …            | The same components, exported one by one under the names their `DataGrid<Name>Props` types already use. `DataGrid.Toolbar` and `DataGridToolbar` are the same value; the named form is what lets a bundler drop the ones you do not render (see below). `DataGridRoot` is the root **without** the statics.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

### Naming a component instead of the namespace

`DataGrid` is one object carrying all 29 components, so a bundler that sees the name keeps every
one of them — that is what a namespace is. Importing the components you actually render lets it
keep only those:

```tsx
import {
	DataGridRoot,
	DataGridTable,
	DataGridHeader,
	DataGridHeaderRow,
	DataGridHeaderCell,
	DataGridBody,
	DataGridRow,
	DataGridCell,
} from '@ez-kit/data-grid-react'
;<DataGridRoot {...config}>
	<DataGridTable>
		<DataGridHeader>
			<DataGridHeaderRow>{(header) => <DataGridHeaderCell header={header} />}</DataGridHeaderRow>
		</DataGridHeader>
		<DataGridBody>
			{(row) => <DataGridRow row={row}>{(cell) => <DataGridCell cell={cell} />}</DataGridRow>}
		</DataGridBody>
	</DataGridTable>
</DataGridRoot>
```

Measured with esbuild, minified and gzipped with React external: `DataGrid` costs 34 272 bytes
whatever a page renders, and a grid composed from ten named components costs 19 265. About 9 500
of either is the shared floor every grid pays, so the components themselves go from ~25 kB to
~10 kB.

Use `DataGridRoot`, not `DataGrid`, as the host — naming the compound anywhere in the tree brings
the other components back. `DataGrid.X` stays supported and is still the shorter thing to write
when a page renders most of the grid anyway.

## Build your own UI flavor

The shadcn and HeroUI flavors are reference implementations of one pattern. To add a third flavor (Mantine, MUI, custom, …):

Components are registered as a **nested, feature-grouped** object. `satisfies FullGridComponents`
is what turns a forgotten component into a compile error rather than a blank space at runtime:

```tsx
// my-flavor/src/data-grid.tsx
import { createDataGrid } from '@ez-kit/data-grid-react'

import { Button, Checkbox, Input, Menu, Modal, NumberInput, Toolbar } from './blocks/core'
import { Table, Tbody, Td, Tfoot, Th, Thead, Tr } from './blocks/core/table-adapters'
import { Pagination, PageSizer } from './blocks/pagination'
// …one module per feature group

import type { FullGridComponents } from '@ez-kit/data-grid-react'

const components = {
	core: { Table, Thead, Tbody, Tfoot, Tr, Th, Td, Button, Input, Checkbox, Toolbar, Menu, NumberInput, Modal },
	pagination: { Pagination, PageSizer },
	// …every other group
} satisfies FullGridComponents

export const { DataGrid, useDataGrid, createColumns, createColumnHelper, extendDataGrid } = createDataGrid({
	components,
})
```

The bundle is what your package exports: its `DataGrid` and `useDataGrid` are pre-bound to your
components, and `createColumns` / `createColumnHelper` are typed to the cell types you registered.
Pass `defaults` as well to bake [kit-level option defaults](/docs/data-grid/state/defaults) into
every grid the kit builds.

The shared React layer renders to your components via `data-*` attributes. Your CSS targets those attributes. The constitution's Principle II keeps the contract clean: **no styling in the shared layer**.

### The shell's two boxes

Around the table the shared layer renders a wrapper and, inside it, the scrollport. Both are
**optional slots**: register nothing and you get plain `div`s, which is all most kits need.

```tsx
core: {
	TableWrapper, // the outer box — the pin-shadow overlay is positioned against it
	TableScroll,  // the scrollport
	// …
}
```

Register one when your kit's own markup has to be there — typically because it nests a scroll
container of its own. Two obligations come with it:

1. **Spread every prop you receive.** `data-slot` above all: the structural stylesheet targets the
   slot, not the element, so the height, overflow and sticky rules follow the attribute onto your
   element. `className` and `style` carry the height custom properties.
2. **Land `ref` on the element that actually scrolls.** That ref is how the shared layer knows
   where the scrollport is — it drives the pin shadows, infinite-scroll edge detection, the row
   virtualizer, and the `data-scrollport` attribute. A kit whose scroller is nested points the ref
   at the nested element, not at its own outermost box.

```tsx
const TableScroll = forwardRef<HTMLDivElement, TableScrollProps>(function TableScroll(props, ref) {
	return (
		<KitTable>
			<KitTable.ScrollContainer
				ref={ref}
				{...props}
			/>
		</KitTable>
	)
})
```

The HeroUI flavor does exactly this, which is why its `Table` slot renders only the table element.
The slot works when your scroller sits at or above the shell's box in your own tree; if it sits
below your table element, hoist the enclosing markup into the slot as that kit does.

### The tooltip

`core.Tooltip` is an optional slot of the same tier — two props, `content` and `children`, and
nothing else. The grid reaches for it where a short readout has a longer form worth showing on
hover; the action bar's pending counts are the first.

Whatever you put around `children` must be **layout-neutral**: the grid hands the slot elements
that already sit in a flex row, so a box of your own between them and their parent must add no
sizing. The shadcn flavor uses its trigger's `asChild` form and adds no element at all; the HeroUI
one wraps, because that primitive draws a focusable box so the hint is reachable by keyboard —
either is fine as long as the row does not move.

Register nothing and the grid renders what the tooltip would have wrapped — the meaning is always
on the element itself, as its accessible name, so what is lost is the hint alone.

## Rules

- This package MUST NOT import any UI kit (constitution Principle I).
- This package MUST NOT author styling (`style={{}}`, a literal `className`, Tailwind) — only
  **semantic `data-*` attributes**, and classes it was _given_ (`layout.classNames`,
  `column.cellClassName`, `rowProps().className`) passed through untouched (constitution
  Principle II).
- Public API is exported exclusively from `src/index.ts`.
