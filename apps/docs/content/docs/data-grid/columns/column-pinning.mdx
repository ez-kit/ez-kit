# Column Pinning

Pinned columns stick to the table edge during horizontal scroll. Useful for keeping an id, name, or row-actions column in view.

## Usage

<DataGridDocsExample exampleId='column-pinning' />

```tsx
const columns = defineColumns<Row>([
	{ accessorKey: 'id', header: 'ID', pinning: { defaultPin: 'left' } },
	{ accessorKey: 'actions', header: 'Actions', pinning: { defaultPin: 'right' } },
])

<DataGrid
	data={data}
	columns={columns}
	pinning={{ column: true }}
/>
```

## Options

| Option                       | Type                                                                   | Description                                                                                                                                  |
| ---------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `pinning` (column def)       | `false \| { pin?: 'left' \| 'right', defaultPin?: 'left' \| 'right' }` | Per-column. `pin` — static, always pinned, no pin section in the column menu. `defaultPin` — starts pinned, user can change it via the menu. |
| `pinning` (table)            | `boolean \| { column?: boolean, row?: … }`                             | Table-level. `{ column: true }` enables the pin section in each column's ⋮ menu.                                                             |
| `initialState.columnPinning` | `{ left?: string[], right?: string[] }`                                | Uncontrolled seed for pinned columns at mount.                                                                                               |
| `state.columnPinning`        | same                                                                   | Controlled pinning state — pass alongside `onStateChange`. No per-feature `onChange`; see [Controlled State](./data-grid/controlled-state).  |

## Notes

The shadcn flavor renders pinned columns by reading `data-pinned` attributes on `<th>`/`<td>` and applying sticky positioning in CSS — this avoids touching the vendored shadcn primitives. The HeroUI flavor does the same against the HeroUI table primitives.

Per [Architecture](./data-grid/architecture) Principle III, pinning overrides live in the flavor's `blocks/` adapters; the vendored shadcn `components/ui/**` files are never modified.
