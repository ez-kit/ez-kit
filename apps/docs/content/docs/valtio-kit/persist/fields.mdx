# Fields (accessor)

The accessor API is the second front on the same engine: no classes, no build-time decorator support required. Pass a builder that declares each field with a typed selector and a **source** helper; the parser type follows the selected leaf, and you get autocomplete on the store shape.

```tsx
import { createStore } from '@ez-kit/valtio-kit'
import { persist } from '@ez-kit/valtio-kit/persist'
import { urlField } from '@ez-kit/valtio-kit/persist/url'
import { localStorageField } from '@ez-kit/valtio-kit/persist/storage'
import { proxy } from 'valtio'

const store = createStore(() => proxy({ q: '', page: 1, pageSize: 25 }), {
	plugins: [
		persist({
			fields: (field) => [
				field((s) => s.q, urlField()), // → ?q=
				field((s) => s.page, urlField()), // auto-resolved number
				field((s) => s.pageSize, localStorageField()), // persisted to localStorage
			],
		}),
	],
})
```

The selector supports **direct property access only** (`s => s.a.b.c`) — it's recorded to derive the path, not executed for its value. Each field's second argument is a source helper (`urlField()`, `localStorageField()`, `sessionStorageField()`, `indexedDbField()`), which returns the `{ source, … }` options the field needs.

<Callout type='info'>
	Same engine, two fronts: decorators for [classes](./valtio-kit/persist/decorators), `field()` for plain proxies. Pick
	per project; mix per store. Sources, parsers, and SSR behave identically.
</Callout>

## Per-field options

The source helper accepts the same options as the matching decorator — `parser`, `key`, `absolute`, `prefix`:

```tsx
import { paramEnum } from '@ez-kit/valtio-kit/persist'

createStore(() => proxy({ filters: { search: { q: '' }, sort: 'asc' as 'asc' | 'desc' } }), {
	plugins: [
		persist({
			fields: (field) => [
				field((s) => s.filters.search.q, urlField({ key: 'q', absolute: true })), // → ?q
				field((s) => s.filters.sort, urlField({ parser: paramEnum(['asc', 'desc']) })),
			],
		}),
	],
})
```

See [Key placement](./valtio-kit/persist/decorators#key-placement) for the full semantics — identical across both fronts.

## Multiple sources, one field

List the same field once per source to dual-bind it (URL when present, restored from storage otherwise):

```tsx
persist({ fields: (field) => [field((s) => s.q, urlField()), field((s) => s.q, localStorageField())] })
```

First-present-wins governs cold start — see [Combined](./valtio-kit/persist/combined#first-present-wins-on-cold-start).
