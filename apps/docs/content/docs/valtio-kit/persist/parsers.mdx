# Parsers

A parser converts one typed leaf to/from a string. The substrate (URL, storage blob, IndexedDB record) only ever stores strings, so the **same** parsers round-trip a value through every source. Reads never throw into render — invalid input falls back to the field's default.

| Parser | Type | Notes |
| --- | --- | --- |
| `paramString()` | `string` | identity |
| `paramNumber()` | `number` | finite numbers; non-finite omitted |
| `paramBoolean()` | `boolean` | also reads `1`/`0` |
| `paramBigInt()` | `bigint` | decimal string |
| `paramDate()` | `Date` | ISO string |
| `paramEnum(values)` | `T` | rejects values outside the set |
| `paramArray(item)` | `T[]` | delimited list of an inner parser |
| `paramJson()` | `T` | JSON value (plain objects/arrays) |

```ts
import { paramArray, paramEnum, paramString } from '@ez-kit/valtio-kit/persist'

const sort = paramEnum(['asc', 'desc'] as const)
const tags = paramArray(paramString())
```

All codecs live on the core `@ez-kit/valtio-kit/persist` entry — they're source-agnostic. Each satisfies a round-trip contract (`parse(stringify(v))` deep-equals `v`), which lets the engine break the proxy⇄substrate loop by comparing serialized forms.

The parsers are exercised live by the [URL deep dive demo](./valtio-kit/persist/deep-dive-url) — an array of tags and an enum sort, encoded into the query string.

## Auto-resolution

When you omit a parser, one is picked from the field's **runtime value** at bind time:

| Value brand | Parser |
| --- | --- |
| `string` | `paramString()` |
| `number` | `paramNumber()` |
| `boolean` | `paramBoolean()` |
| `bigint` | `paramBigInt()` |
| `Date` instance | `paramDate()` |
| array (non-empty) | `paramArray(<item>)`, item inferred from the first element |

Anything else — `null`, `undefined`, a plain object, `Set`/`Map`, an empty array, or a class instance with no persisted fields — **throws at bind** with the field name and asks for an explicit parser:

```tsx
@persistUrl({ parser: paramJson() }) coords = { lat: 0, lng: 0 } // plain object → explicit
@persistUrl() createdAt = new Date() // Date → auto
```

<Callout type="warn">
	Auto-resolution can't read your TypeScript types, only runtime values. A field typed `string | null` that
	starts `null` has no brand to resolve — give it an explicit parser.
</Callout>

## Zod validation

`zodParam(schema)` turns any Zod schema into a parser — parsing **is** validation, and a failed parse gracefully falls back to the default.

<LivePreview path='valtio-kit/persist-zod' title='Zod-validated rating (1–5)' />

```ts
import { zodParam } from '@ez-kit/valtio-kit/persist/validators/zod'
import { z } from 'zod'

const rating = zodParam(z.coerce.number().int().min(1).max(5))
```

`zod` is an optional peer — import `zodParam` from the dedicated subpath only if you use it.

## Custom parsers

A parser is a small object: `parse(string) → value`, `stringify(value) → string` (return `null` to omit the key), and an optional `equals`. Honor the round-trip contract so the loop terminates:

```ts
import type { Parser } from '@ez-kit/valtio-kit/persist'

const csv: Parser<string[]> = {
	parse: (raw) => (raw ? raw.split(',') : []),
	stringify: (value) => (value.length ? value.join(',') : null),
	equals: (a, b) => a.length === b.length && a.every((x, i) => x === b[i]),
}
```

A non-canonical parser (one whose `stringify` output isn't stable) can loop — supply `equals`, or lean on `paramJson()`, which uses stable key ordering for you.
