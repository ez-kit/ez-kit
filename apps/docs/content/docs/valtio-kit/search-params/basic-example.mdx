# Basic example

The quickest way in: decorate the fields you want synced, hand the proxy to a request-scoped store, and render it under the coordinator. Mutating the proxy updates the URL; deep links and Back/forward update the proxy.

<LivePreview path='valtio-kit/search-params-decorators' title='URL-synced filters' />

<Callout type="warn">
	The interactive demo above is declared with the [accessor API](./valtio-kit/search-params/fields) so it runs in
	this in-browser sandbox; `@searchParam` needs a build-time decorator transform. The behavior and URL output are
	identical — the snippet below shows the recommended decorator form.
</Callout>

## The three pieces

```tsx
import {
	createDecoratedStore,
	searchParam,
	StoreSearchParamsProvider,
} from '@ez-kit/valtio-kit/search-params'
import { proxy } from 'valtio'

// 1. Decorate the fields to sync. Primitives need no parser — it's auto-resolved.
class Filters {
	@searchParam() q = ''
	@searchParam() page = 1
	@searchParam() inStock = false
}

// 2. Build a request-scoped store. Omit `fields` → decorators are discovered on the instance.
const filtersStore = createDecoratedStore(() => proxy(new Filters()))

// 3. Render under the coordinator with a router adapter (here, the real app uses nextAdapter
//    or reactRouterAdapter; the live demo above swaps in an in-memory one).
function Page() {
	return (
		<StoreSearchParamsProvider adapter={adapter}>
			<filtersStore.Provider>
				<Filters />
			</filtersStore.Provider>
		</StoreSearchParamsProvider>
	)
}
```

Inside, read with `useSnapshot()` and write through `useStore()`:

```tsx
function FilterControls() {
	const snap = filtersStore.useSnapshot()
	const store = filtersStore.useStore()
	return (
		<input
			value={snap.q}
			onChange={(event) => {
				store.q = event.target.value // → ?q=…
			}}
		/>
	)
}
```

## Where to go next
