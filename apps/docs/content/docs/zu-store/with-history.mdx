# `withHistory` and `useHistoryStore`

`withHistory` wraps a Zustand store and adds **undo / redo** plus a separate history store. Every call to `setState` (or the returned `set`) is recorded by default; you can pause, predicate-filter, or opt-out of individual writes.

`useHistoryStore` is the React hook for subscribing to that history store.

## `withHistory`

### Signature

```ts
function withHistory<T extends object>(store: StoreApi<T>, options?: HistoryOptions<T>): HistoryStore<T>

type HistoryOptions<T> = {
	/** Maximum number of past states to keep. Defaults to 100. */
	limit?: number
	/** Start history recording paused. Defaults to false. */
	defaultPaused?: boolean
	/** Pre-populate the pasts stack. Entries exceeding limit are trimmed from the front. */
	defaultPasts?: T[]
	/** Pre-populate the futures stack. */
	defaultFutures?: T[]
	/** Return false to skip recording this particular change. */
	shouldPush?: (prev: T, next: T) => boolean
}

type HistoryStore<T extends object> = Omit<StoreApi<T>, 'setState'> & {
	setState: {
		(partial: T | ((state: T) => T), replace: true, options?: SetOptions): void
		(partial: T | Partial<T> | ((state: T) => T | Partial<T>), replace?: false, options?: SetOptions): void
	}
	set: (partial: Partial<T> | ((state: T) => Partial<T>), options?: SetOptions) => void
	history: StoreApi<HistoryState<T>>
}

type SetOptions = {
	/** When true the setState call is not recorded in history. */
	skipHistory?: boolean
}
```

### Options

#### `limit`

Caps the number of past states. When a new entry would exceed the limit, the oldest entry is dropped (FIFO). Defaults to `100`. Excess entries from `defaultPasts` are trimmed from the **front**.

```ts
withHistory(store, { limit: 25 })
```

#### `shouldPush`

A predicate run before each recording. Return `false` to keep the state change but skip the history entry. Useful for collapsing high-frequency updates (typing, drag deltas) into a single undo step.

```ts
withHistory(store, {
	shouldPush: (prev, next) => prev.kind !== next.kind, // record only on shape change
})
```

#### `defaultPaused`

Start the history paused. Combine with `history.resume()` once your initial bootstrap finishes:

```ts
const store = withHistory(rawStore, { defaultPaused: true })
hydrateFromServer()
store.history.getState().resume()
```

#### `defaultPasts` / `defaultFutures`

Pre-populate the stacks. Handy when restoring a session.

```ts
withHistory(store, {
	defaultPasts: [{ count: 0 }, { count: 1 }],
})
```

### `SetOptions.skipHistory`

Both `setState` and `set` accept an options object as the **last** argument. `skipHistory: true` writes to the store without producing a history entry — for example, when applying server-pushed updates that the user shouldn't be able to undo.

```ts
counterStore.set({ count: 0 }, { skipHistory: true })
counterStore.setState({ count: 0 }, false, { skipHistory: true })
```

## `useHistoryStore`

React hook that subscribes to the embedded `history` store. Read the full state or a selected slice.

### Signature

```ts
function useHistoryStore<T extends object>(store: HistoryStore<T>): HistoryState<T>
function useHistoryStore<T extends object, S>(store: HistoryStore<T>, selector: (state: HistoryState<T>) => S): S

type HistoryState<T> = {
	readonly pasts: readonly T[]
	readonly futures: readonly T[]
	readonly limit: number
	readonly isPaused: boolean
	undo: () => void
	redo: () => void
	clear: () => void
	pause: () => void
	resume: () => void
}
```

### Usage

```tsx
// Whole history state — re-renders on any history change.
const history = useHistoryStore(counterStore)

// Slice — re-renders only when the slice changes.
const canUndo = useHistoryStore(counterStore, (h) => h.pasts.length > 0)
const undo = useHistoryStore(counterStore, (h) => h.undo)
```

`undo`, `redo`, `clear`, `pause`, and `resume` are stable references on the history store, so you can pass them to event handlers without worrying about stale closures.

## Combining with `createContextStore`

`withHistory` returns a Zustand-compatible store, so it composes naturally with `createContextStore`:

```ts
import { createContextStore, withHistory } from '@ez-kit/zu-store'
import { createStore } from 'zustand/vanilla'

interface DraftState {
	title: string
}

const draftStore = createContextStore(({ initialTitle = '' }: { initialTitle?: string }) =>
	withHistory(createStore<DraftState>()(() => ({ title: initialTitle })), { limit: 50 }),
)

function TitleField() {
	const store = draftStore.useContextStore()
	const title = draftStore.useStore((s) => s.title)
	return <input value={title} onChange={(e) => store.set({ title: e.target.value })} />
}
```

Each `<draftStore.Provider>` now has its own history stack — undoing in one panel does not affect another.
