A tiny layer on top of [Zustand](https://github.com/pmndrs/zustand) that:

- wraps a vanilla store in **React context**, so multiple isolated instances can coexist in the same tree;
- exposes a [`useState`](https://react.dev/reference/react/useState)-style hook for binding a **single store field**;
- ships a real **`withHistory`** Zustand middleware for undo / redo / goto, records actions automatically, composes with `persist` / `devtools` / `subscribeWithSelector`;
- can **keep stores alive** across `Provider` unmount/remount with `createStoreCache`, so navigation state (filters, pagination) survives without `localStorage`;
- can **persist** any field to the URL, `localStorage` / `sessionStorage`, IndexedDB or your own substrate, through one `withPersist` capability with typed codecs.

It exists because plain Zustand stores are module-level singletons by default — fine for app-wide state, awkward when you want a counter, modal, or form scoped to a subtree.

## Install

```bash
pnpm add @ez-kit/zu-store zustand
```

`zustand` is a peer dependency — pin whatever 5.x version your app already uses.

→ **[Getting Started](./zu-store/getting-started)** — install, your first store, and the read/write model.

## Why not plain Zustand?

Plain Zustand stores live at module scope. Two `<Modal>` instances or two `<DataGrid>` instances would share one store and stomp on each other. `createContextStore` defers store creation to the `Provider`, so each mount gets its own instance — without forcing you to drill props through the tree.
