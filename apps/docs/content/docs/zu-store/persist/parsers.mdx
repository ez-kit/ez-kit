A parser converts one typed leaf to/from a string. The substrate (URL, storage blob, IndexedDB record) only ever stores strings, so the **same** parsers round-trip a value through every source. Reads never throw into render — invalid input falls back to the field's default.

| Parser              | Type      | Notes                                            |
| ------------------- | --------- | ------------------------------------------------ |
| `paramString()`     | `string`  | identity                                         |
| `paramNumber()`     | `number`  | finite numbers; invalid/non-finite input rejects |
| `paramBoolean()`    | `boolean` | also reads `1`/`0`                               |
| `paramBigInt()`     | `bigint`  | decimal string                                   |
| `paramDate()`       | `Date`    | ISO string                                       |
| `paramEnum(values)` | `T`       | rejects values outside the set                   |
| `paramArray(item)`  | `T[]`     | delimited list of an inner parser                |
| `paramJson()`       | `T`       | JSON value (plain objects/arrays)                |

```ts
import { paramArray, paramEnum, paramString } from '@ez-kit/zu-store/persist'

const sort = paramEnum(['asc', 'desc'] as const)
const tags = paramArray(paramString())
```

Array equality composes the item codec's equals, so Date arrays and nested/object codecs restore
and clear their defaults by value. Ordinary delimited arrays keep their existing readable encoding.
Exceptional values such as a singleton empty string, or separators that collide with URI escapes,
use a tagged JSON frame of item strings. The frame is parser-owned, not a record version manifest;
legacy unambiguous delimited values remain readable. Empty arrays still omit the key, and a legacy
raw empty string still decodes to an empty array. New framed writes require the updated decoder;
retain the old namespace when planning rollback.

All codecs live on the core `@ez-kit/zu-store/persist` entry — they're source-agnostic. Each satisfies a round-trip contract (`parse(stringify(v))` deep-equals `v`), which lets the engine break the store⇄substrate loop by comparing serialized forms.

The catalogue is exercised live below: `q`, `page` and `inStock` auto-resolve from their runtime values, while the array of tags and the closed enum carry an explicit codec.

## Auto-resolution

When you omit a parser, one is picked from the field's **runtime value** at bind time:

| Value brand       | Parser                                                     |
| ----------------- | ---------------------------------------------------------- |
| `string`          | `paramString()`                                            |
| `number`          | `paramNumber()`                                            |
| `boolean`         | `paramBoolean()`                                           |
| `bigint`          | `paramBigInt()`                                            |
| `Date` instance   | `paramDate()`                                              |
| array (non-empty) | `paramArray(<item>)`, item inferred from the first element |

Anything else — `null`, `undefined`, a plain object, `Set`/`Map`, or an empty array — **throws at bind** with the field name and asks for an explicit parser:

```tsx
field((state) => state.coords, urlField({ parser: paramJson() })) // plain object → explicit
field((state) => state.createdAt, urlField()) // Date → auto
```

<Callout type='warn'>
	Auto-resolution can't read your TypeScript types, only runtime values. A field typed `string | null` that starts
	`null` has no brand to resolve — give it an explicit parser.
</Callout>

## Zod validation

Decode first, migrate older versions if needed, then validate the current shape through
`schema.validate`. Zod is an application dependency; persist does not import it.

/>

```ts
import { paramNumber } from '@ez-kit/zu-store/persist'
import { z } from 'zod'

const ratingSchema = z.number().int().min(1).max(5)
field((state) => state.rating, {
	source: 'url',
	parser: paramNumber(),
	schema: { validate: (value) => ratingSchema.parse(value) },
})
```

For versioned objects use `paramJson()` and place version, migrate and validate together in schema.
A future version is left untouched; a bad current value invalidates only its record.

## Custom parsers

A parser is a small object: `parse(string) → value`, `stringify(value) → string` (return `null` to omit the key), and an optional `equals`. Honor the round-trip contract so the loop terminates:

```ts
import type { Parser } from '@ez-kit/zu-store/persist'

const visibility: Parser<'shown' | 'hidden'> = {
	parse(raw) {
		if (raw === '1' || raw === 'shown') return 'shown'
		if (raw === '0' || raw === 'hidden') return 'hidden'
		throw new Error('Invalid visibility')
	},
	stringify: (value) => (value === 'shown' ? '1' : '0'),
}
```

A non-canonical parser (one whose `stringify` output isn't stable) can loop — supply `equals`, or lean on `paramJson()`, which uses stable key ordering for you.

`paramJson` compares serialized values, including Date/toJSON results, nested containers and own
special keys. A `schema.validate` function can return a Date: changing its timestamp saves the new
JSON value; returning to the serialized default removes the override.
