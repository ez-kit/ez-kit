Mirror a Zustand store into an external substrate and back, in both directions. A `set()` writes the substrate; restoration or URL navigation writes the store. Ambient external changes require an explicit apply policy. The store stays **synchronous and snappy** — the substrate is a throttled, rehydratable projection of it.

```bash
pnpm add @ez-kit/zu-store zustand
```

Router integrations are optional peers (`react-router`, `next`). Zod can be an application dependency used by schema.validate.

## One engine, many sources

The core never imports React, `URLSearchParams`, or a storage API. Its only interchange language is `Keyed = Map<string, string>` — a logical key mapped to an already-stringified value. A **source adapter** teaches the engine how to read and write one substrate through a small port (`get` / `set` / `subscribe`). Everything else — typed codecs, key naming, throttling, loop-breaking, hydration — is shared.

| Source                        | Import                             | Sync?  |
| ----------------------------- | ---------------------------------- | ------ |
| URL search params             | `@ez-kit/zu-store/persist/url`     | sync   |
| localStorage / sessionStorage | `@ez-kit/zu-store/persist/storage` | sync   |
| IndexedDB                     | `@ez-kit/zu-store/persist/storage` | async  |
| your own                      | a `SourcePort` you write           | either |

Because each source is just an adapter, a single field can sync to **two** substrates at once (a shared `?q=` in the URL _and_ a cached copy in storage), and async sources (IndexedDB) never stall the synchronous URL.

## How it works

The store is the **source of truth**; the substrate is a **mirror**. When you write to the store, the change is synced to the substrate. When the substrate changes externally (a deep link, browser back button, another tab), the change is synced back to the store — and only the components that read a changed field re-render.

## Declaring fields

You bring your own store and declare which fields sync, with the [accessor front](./persist/fields): `field((state) => state.q, urlField())`. The selectors are typed against the store's **state**, not its handle — `withPersist` reads `ExtractState` off the store `pipe` hands it.

<Callout type='info'>
	The decorator front (`@persistUrl()` on a class property) is deliberately Valtio-only: it is the "class inside
	`proxy()`" idiom, and Zustand state is a plain object rebuilt on every write. The accessor front is the same engine
	and the same descriptors — see [va-store → decorators](../va-store/persist/decorators) if you are comparing the two
	packages.
</Callout>

## The same engine as va-store

Both packages re-export `@ez-kit/store-persist` with their own store port bound, so codecs, adapters, key naming, migrations, `useHydrated` and the `$url` / `$persist` handles behave identically. Only two things are Zustand-specific: how a write happens (`set()`, a new state object) and how the capability is attached (`pipe(store, withPersist())` on the handle).

## Scoped state, restore and reset

Register adapters by name and choose a default source. Cached store addresses automatically include
scope, group name, instance id and field; no hand-built persistence prefix is needed.

```tsx
<StoreProvider
	persist={{ browser: browserAdapter, server: serverAdapter }}
	defaultSource='browser'
	cache={cache}
>
	<cache.Scope path={['devices']}>
		<panel.Provider id='workspace'>{children}</panel.Provider>
	</cache.Scope>
</StoreProvider>
```

Use schema.version/migrate/validate for independently versioned values. Restoration starts automatically;
configure restore.timeoutMs and read usePersistStatus for a loader. Timeout does not save defaults and
late reads do not change an active layout. useHydrated means all initial sources stopped waiting,
including timeout/error, rather than claiming every read succeeded.

Use persistHandle(store, source).reset() to restore initialization defaults and delete overrides.
Use `usePersistence().resetScope({ path: ['devices'], sources: ['browser', 'server'] })` for the whole
page, including descendants and saved states without mounted components. Await flush() for confirmed
writes. Failed I/O keeps memory usable and exposes status/error; reset is distinct from cache eviction.

Source registration is stable for a Provider lifetime. Remount its cache too on account/backend changes.
This release deliberately makes breaking changes in a minor: new storage addresses/patch semantics,
removed zodParam subpath, automatic restore/status and explicit ambient external-change policy.
Keep a lockfile or pin old bindings until the application is ready; prefer a new storageKey for rollout.
