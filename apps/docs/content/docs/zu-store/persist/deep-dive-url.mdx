## History: push vs replace

By default a commit **replaces** the current history entry, so typing in a search box doesn't stack dozens of Back steps. Opt a field into `push` so each change is a distinct, back-button-able entry:

```tsx
import { UrlHistory, urlField } from '@ez-kit/zu-store/persist/url'

withPersist({
	fields: (field) => [field((state) => state.step, urlField({ history: UrlHistory.Push }))],
})
```

When several field changes coalesce into one navigation, any `push` in the batch makes the whole navigation a push.

## Key naming

Nested state maps to **dotted** keys by path: `price.min` → `?price.min=`. A URL pull rebuilds only the touched path, so a selector reading a sibling branch does not re-render. The three key-shaping options (`key`, `prefix`, `absolute`) are on [Fields → key placement](./fields#key-placement); they are source-agnostic and apply to storage too.

## Router adapters

A render-scoped adapter turns router hooks into a port. Two ship in the box; both are optional peers.

```tsx
// react-router v6/v7 (BrowserRouter / data routers)
import { reactRouterAdapter } from '@ez-kit/zu-store/persist/url/react-router'
;<StoreProvider persist={[reactRouterAdapter]}>…</StoreProvider>
```

```tsx
// Next.js App Router
import { nextAdapter } from '@ez-kit/zu-store/persist/url/next'
;<StoreProvider persist={[nextAdapter]}>…</StoreProvider>
```

Render-scoped adapters call hooks, so the `persist` array must be stable in length and order. To target a different router, [write your own adapter](./custom-adapter#render-scoped-url-adapters).

## Imperative control via `$url`

`withPersist` attaches both control handles — `$url` and `$persist` — right on the returned store handle, typed on its return value: `store.$url` type-checks straight off `useStore()`, no accessor needed. Run a mutation whose resulting commit carries explicit `meta`, e.g. forcing a one-off `push` regardless of the field's default:

```tsx
import { UrlHistory } from '@ez-kit/zu-store/persist/url'

function next() {
	const store = wizardStore.useStore()
	store.$url.runWithMeta({ history: UrlHistory.Push }, () => {
		store.setState({ step: 'profile' })
	})
}
```

Before the provider connects (server render, first paint) the handle is inert — the mutation still runs, just without engine meta. A store with no URL-bound field still carries `$url`, with `source: null`; it stays permanently inert.

If the handle's type has been widened away — passed through a function typed as a plain `StoreApi<T>`, say — resolve it with the typed `urlHandle()` accessor instead; it throws only when the store never went through `withPersist` at all:

```tsx
import { urlHandle } from '@ez-kit/zu-store/persist'

urlHandle(store).runWithMeta({ history: UrlHistory.Push }, () => {
	store.setState({ step: 'profile' })
})
```

## SSR

A `createContextStore` store wrapped in `withPersist` is request-scoped: each `Provider` mount creates its own store, so concurrent requests never share state. The URL source seeds **synchronously** in render, so server HTML reflects the incoming query string and the first client render matches it — no flash, no hydration mismatch. (Storage sources defer to mount; see the [storage deep dive](./deep-dive-storage).)
