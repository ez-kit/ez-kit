# Getting Started

`@ez-kit/zu-store` wraps a vanilla [Zustand](https://github.com/pmndrs/zustand) store in **React context** so multiple isolated instances of the same state can coexist in one tree, scoped by `Provider`. This page gets you from install to a working store.

## Install

```bash
pnpm add @ez-kit/zu-store zustand
```

`zustand` is a **peer dependency** — pin whatever 5.x version your app already uses. Router, storage and validator integrations used by [Persist](./persist) are optional peers; install only what you reach for (`react-router`, `next`, `zod`).

## Your first store

`createContextStore(factory)` takes a factory that returns a vanilla Zustand store and hands back a `Provider` plus hooks. Each `Provider` mount calls the factory again, so two of them never share state.

```tsx
import { createContextStore, type ContextStoreInit } from '@ez-kit/zu-store'
import { createStore } from 'zustand/vanilla'

type CounterState = { count: number; increment: () => void }

const counterStore = createContextStore(({ defaultValue }: ContextStoreInit<{ count?: number }>) =>
	createStore<CounterState>()((set) => ({
		count: defaultValue.count ?? 0,
		increment: () => {
			set((state) => ({ count: state.count + 1 }))
		},
	})),
)
```

## The read/write model

Zustand notifies every subscriber on every write, so a read has to say **what** it cares about — that is what the selector is for:

| Action | How                                                                                                       |
| ------ | --------------------------------------------------------------------------------------------------------- |
| Read   | `store.useSelector((state) => state.count)` → re-renders only when the selected value changes             |
| Read   | `store.useShallowSelector((state) => ({ a, b }))` → same, compared shallowly, for object/array selections |
| Write  | `store.useStore().setState(…)`, or an action declared in the store — the raw handle, no subscription      |

`useStore()` returns the **raw `StoreApi`** and does **not** subscribe the calling component; pair it with `useSelector()` when the same component also has to render. `Subscribe` is the render-prop form of `useSelector`.

Coming from [`@ez-kit/va-store`](../va-store)? The write path is spelled the same (`useStore()`), only the read path differs: a selector here, a tracked `useSnapshot()` there.

## Binding a single field

For form-shaped state, [`useStoreState`](./use-store-state) collapses the selector-plus-`setState` pair into the `useState` tuple you already know:

```tsx
const [name, setName] = useStoreState(store.useStore(), 'name')
```
