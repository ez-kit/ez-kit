# Native API

The flat fields are **added to** the TanStack Form instance, not layered over it. Everything the native API gives you is on the same object, unchanged:

| Member               | Still there                                                            |
| -------------------- | ---------------------------------------------------------------------- |
| `form.Field`         | The render-prop field, for markup the flat fields do not cover.        |
| `form.Subscribe`     | Selector-based subscription — see [Reactivity](/docs/form/reactivity). |
| `form.handleSubmit`  | Submit programmatically.                                               |
| `form.state`         | The current snapshot (not reactive on its own).                        |
| `form.setFieldValue` | …and the rest of the imperative API.                                   |
| `form.AppField`      | TanStack's own component-bound field.                                  |

## `form.Field`

Use it whenever you need a control we do not ship — a segmented picker, a slider, a colour input:

```tsx
<form.Field name='seats'>
	{(field) => (
		<MySegmentedControl
			value={field.state.value}
			onChange={field.handleChange}
			onBlur={field.handleBlur}
			invalid={field.state.meta.errors.length > 0}
		/>
	)}
</form.Field>
```

You own the chrome here — label, description and error rendering are up to you. If you want the flat fields' layout and error handling around your own control, [write a kit](/docs/form/custom-kit) instead.

## Reading state

`form.state` read in a component body is a snapshot, not a subscription: the component will not re-render when the value changes. Anything you render from form state goes through `form.Subscribe`, which is the subject of [Reactivity](/docs/form/reactivity).

## Submitting from elsewhere

`<Form>` wires submission for you, but nothing stops you calling it yourself — from a toolbar button, a keyboard shortcut, a dialog footer that sits outside the element:

```tsx
<button
	type='button'
	onClick={() => void form.handleSubmit()}
>
	Save
</button>
```

And if you would rather own the `<form>` element entirely, skip `<Form>` — take the instance from `useForm` and render your own:

```tsx
<form
	onSubmit={(event) => {
		event.preventDefault()
		event.stopPropagation()
		void form.handleSubmit()
	}}
>
	<form.TextField
		name='email'
		label='Email'
	/>
</form>
```

The flat fields do not care which element they sit in — they bind to the form instance, not to the DOM node.

## Composition helpers

All four of TanStack's composition helpers — `withForm`, `withFieldGroup`, `useFormGroup` and `useFieldGroup` — are shipped by your kit package, with `withForm` retyped so the flat fields compile inside a block. They have a page of their own: [Composition](/docs/form/composition).
